## 一句话说清

DPO 训练让模型更偏向人认为更好的回答。这本 notebook 教你判断它的结果能不能交付：数据和评测要隔开，质量、资源和产物要同时过关。

## 为什么需要它

62 节交付了一份 SFT 基线。接下来你可能想让它更符合人的喜好：同一个问题给出两个回答，人标出哪个更好。DPO（直接偏好优化）就用这种成对的数据继续训练，目标是让模型更偏向优选的那个。

训练完要下结论，有三个坑：

- 评测题混进了训练集。模型见过这道题，评测分数再高也说明不了问题。
- 只看平均分。平均边际在涨，但最差的那一对评测对退化了，平均分会把它盖住。
- 质量好了就忽略资源和产物。质量通过但显存越界，或者适配器文件没保存好，结果仍然不能用。

这本 notebook 解决的是“怎样下结论”：把数据隔离、质量、资源和产物分开检查，再按顺序给出 `reject`（拒绝）、`tune`（调优）或 `accept`（接受）。

## 先认识几个词

| 词 | 人话解释 |
|:---|:---|
| 偏好对 | 同一个问题配两个回答，一个标记为优选，一个标记为拒绝 |
| 边际（margin） | 每个评测对上的一个数，notebook 里叫“回答词元平均对数概率边际”。大于 0 表示模型更偏向优选回答 |
| 偏好准确率 | 边际大于 0 的评测对所占的比例 |
| 策略（policy） | 正在被更新的那份模型 |
| 参考模型（reference model） | 从 SFT 基线复制出来、训练中冻结不更新的那份 |
| 截断率 | 输入超过长度上限、被截掉的比例 |
| `accept` / `tune` / `reject` | 决策的三种结果：接受、调优、拒绝 |

## 核心思路

输入有两类。一类是数据：训练和评测各自的偏好对编号、问题编号。另一类是证据：更新前后在同一组独立评测对上的边际，加上运行状态、截断率、峰值显存和适配器的路径、哈希。你依次做三次判断，输出是三种决定之一。

```text
数据准入 → 候选门槛 → 交付决策
```

边际是一个列表，每个评测对一个数。骨架代码先把它压缩成三个数，再用“更新后减去更新前”得到变化量：

```text
偏好准确率 = 边际 > 0 的评测对数 / 评测对总数
平均边际   = 所有评测对的边际之和 / 评测对总数
最差边际   = 所有评测对的边际里最小的那个
变化量     = 候选的值 - 更新前基线的值
```

“候选”是更新后的模型，“更新前基线”是还没做 DPO 的那份。看一个小例子，数字取自 notebook 的测试：

```python
baseline = [-0.20, 0.00, 0.20, 0.40]     # 更新前：4 个评测对各自的边际
candidate = [-0.19, 0.05, 0.25, 0.45]    # 更新后：同一组评测对

def summarize(m):
    return {"accuracy": sum(x > 0 for x in m) / len(m),   # 边际大于 0 的比例
            "mean": sum(m) / len(m),
            "min": min(m)}

before, after = summarize(baseline), summarize(candidate)
print({k: round(v, 2) for k, v in before.items()})
print({k: round(v, 2) for k, v in after.items()})
print({k: round(after[k] - before[k], 2) for k in before})

# 均值改善了，但最差的那一对退化了
tail = summarize([-0.21, 0.05, 0.25, 0.47])
print(round(tail["mean"] - before["mean"], 2), round(tail["min"] - before["min"], 2))
```

```text
{'accuracy': 0.5, 'mean': 0.1, 'min': -0.2}
{'accuracy': 0.75, 'mean': 0.14, 'min': -0.19}
{'accuracy': 0.25, 'mean': 0.04, 'min': 0.01}
0.04 -0.01
```

更新前 4 个评测对里只有 2 个边际大于 0，准确率是 0.5；更新后是 3 个，0.75。三个变化量分别是 0.25、0.04、0.01，对照测试里的门槛（至少 0.05、至少 0.02、不低于 0.0）都通过。

最后一行是“均值改善但尾部退化”：把第一个评测对的边际降到 -0.21，最后一个提到 0.47。平均边际的变化量还是 0.04，最差边际的变化量却变成 -0.01，低于 0.0，这个候选就不合格。

最后一步是交付决策，按顺序判断：

```text
数据没通过、执行失败或产物缺失 → reject
候选门槛没通过               → tune
全部通过                     → accept
```

数据泄漏、执行失败或适配器缺失会让候选不可复现，所以直接拒绝。质量、截断或资源没达标时，已有训练证据还能用来调参，所以是调优。`accept` 之后，候选进入 86 节的生命周期交接；notebook 说明最终采用判断留给 Part 05。

## 容易踩的坑

- **只查偏好对，不查问题**：同一偏好对或同一任务输入跨集合出现，都会污染独立评测。测试覆盖了“同问题换回答”的情况：偏好对不同，问题相同，也不通过。
- **用平均改善掩盖尾部退化**：平均边际提高，不能抵消最差边际下降。门槛是预先给定的，等于门槛也算通过。
- **用质量收益抵消显存越界**：显存上限是 10000 时，10001 不通过，10000 通过。质量再好也不能抵消。
- **把三种结果混为一谈**：交付判断不是加权总分。数据、执行或产物失败是 `reject`，质量、截断或资源没达标是 `tune`，全部成立才是 `accept`。
- **混用两种口径**：边际用的是回答词元平均对数概率的口径，notebook 提醒不要和按整条序列求和的口径直接比较。
