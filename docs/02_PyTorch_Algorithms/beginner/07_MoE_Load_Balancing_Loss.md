## 一句话说清

MoE 的路由器可能“偏科”：把大部分词元都送给少数几个专家。这本 notebook 算一个衡量“偏得多厉害”的损失，并用各专家的忙闲程度去调整下一轮的选择。

## 为什么需要它

上一节的路由器会给每个词元挑 `K` 个专家，但它只管单个词元。训练久了，路由器可能学会“偏科”：大部分词元都被送去少数几个专家，其他专家长期拿不到样本。MoE 表面上有很多参数，实际只剩下少数专家在干活。

这会带来三个问题：

- **拥塞**。被挤的专家先触及容量，容量溢出、排队、跨卡通信和同步长尾都会放大。
- **只看一个数会误判**。路由器给每个专家的平均概率看着是均匀的，可实际选出来的却可能集中在两个专家。只看概率，看不出问题。
- **纠偏有代价**。用损失去约束，系数太大会干扰主任务；用偏置去调整，偏置更新可能振荡。容量回退只保护当前这一批能跑，不能替代长期均衡。

这本 notebook 把“偏好”和“实际分配”两个量算出来，合成一个辅助损失，再做一步无辅助的偏置更新。

## 先认识几个词

| 词 | 人话解释 |
|:---|:---|
| 负载（load） | 一个专家本轮被分到多少次。大家都差不多叫均衡，少数专家特别忙叫拥塞 |
| 平均偏好 `P_i` | 路由器给第 `i` 个专家的平均概率。它说明路由器“想”把词元送去哪 |
| 实际分配比例 `f_i` | 第 `i` 个专家在全部 Top-K 选择里占的比例。它说明词元“实际”去了哪 |
| 辅助损失（auxiliary loss） | 加在训练总损失上的额外一项，用来鼓励均衡。系数 `alpha` 控制它的分量 |
| 主任务 / 主损失 | 模型本来要训练的目标，辅助损失只是附加项 |
| 路由偏置（router bias） | 每个专家一个数，参与专家选择。调高它，这个专家更容易被选中 |
| 无辅助均衡 | 不往损失里加东西，只按历史负载调整路由偏置 |

## 核心思路

输入是一批词元的完整概率 `[T, E]` 和它们选中的专家编号 `[T, K]`。`T` 是词元数，`E` 是专家数，`K` 是每个词元选几个专家（`top_k`）。

```text
P_i        = (1/T) * Σ_t p[t, i]              # 第 i 个专家的平均概率，总和为 1     TODO 1
f_i        = 第 i 个专家被选中的次数 / (T * K)   # 实际分配比例，总和为 1            TODO 2
L_balance  = alpha * E * Σ_i f_i * P_i          # 同一专家上相乘，再求和           TODO 3
```

符号说明：`p[t, i]` 是第 `t` 个词元给第 `i` 个专家的概率；`alpha` 是损失系数，默认 `0.01`。`P_i` 和 `f_i` 要按同一个专家维度对齐。偏好和分配都均匀时，损失正好是 `alpha`；偏好和分配同时集中时，惩罚变大。

另一个函数 `update_router_bias` 不动损失，只动下一轮的选择偏置：

```text
load_error   = (负载 - 平均负载) / max(平均负载, 1)   # 相对平均负载误差
updated_bias = 偏置 - step_size * load_error           # 过载的降，欠载的升    TODO 4
```

下面用 4 个词元、8 个专家、每个词元选 2 个专家，把两个函数各算一遍：

```python
import torch
import torch.nn.functional as F

alpha, E = 0.01, 8          # 损失系数、专家数
even = torch.full((4, E), 1 / E)               # 偏好均匀
sharp = torch.zeros(4, E)                      # 偏好集中在前两个专家
sharp[:, :2] = 0.5

def balance(probs, selected):
    P = probs.mean(dim=0)                                    # 平均偏好，总和为 1
    f = F.one_hot(selected, E).sum(dim=(0, 1)).float() / (4 * 2)   # 实际分配比例，总和为 1
    return P, f, alpha * E * (f * P).sum()

print(balance(even, torch.tensor([[0, 1], [2, 3], [4, 5], [6, 7]]))[2])
print(balance(sharp, torch.tensor([[0, 1]] * 4))[2])
P, f, _ = balance(even, torch.tensor([[0, 1]] * 4))
print(P[:3], f[:3])

counts, bias, step = torch.tensor([8.0, 4.0, 2.0, 2.0]), torch.zeros(4), 0.1
mean = counts.mean()
load_error = (counts - mean) / mean.clamp_min(1.0)
print(load_error, bias - step * load_error)     # 原偏置全是 0
```

```text
tensor(0.0100)
tensor(0.0400)
tensor([0.1250, 0.1250, 0.1250]) tensor([0.5000, 0.5000, 0.0000])
tensor([ 1.0000,  0.0000, -0.5000, -0.5000]) tensor([-0.1000,  0.0000,  0.0500,  0.0500])
```

前两行：均匀路由的损失是 `0.0100`，正好等于 `alpha`；集中路由是 `0.0400`。第三行是“偏好和分配错配”：`P_i` 个个都是 `0.1250`，看起来很均匀，`f_i` 却是 `0.5000`、`0.5000`、`0.0000`。最后一行：负载为 `8` 的专家超出平均，偏置被调低 `0.1`；负载为 `2` 的两个专家低于平均，偏置被调高 `0.05`；负载为 `4` 的专家正好在平均上，偏置不变。

## 容易踩的坑

- **用概率代替分配**：`f_i` 要按 `tokens × top_k` 次选择归一化，不能用概率质量替代。偏好均匀时，离散分配仍可能集中。
- **`P_i` 和 `f_i` 没有对齐**：两者要来自同一专家维度，相乘才有意义。`P_i` 的总和是 1，`f_i` 的总和也是 1。
- **分母用错**：`f_i` 的分母是总分配数，也就是词元数乘 `top_k`，不是词元数。
- **偏置更新的方向反了**：过载专家的偏置要降低，欠载专家的偏置要提高，负载正好等于平均值时不变。
- **把均衡当成万能**：系数太大会干扰主任务，均衡也不等于语义路由正确。容量回退只保护当前批次可执行，不能替代长期均衡。
