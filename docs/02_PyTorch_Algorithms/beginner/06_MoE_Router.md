## 一句话说清

MoE 把大模型里的前馈网络拆成几个“专家”，每个词元只交给其中最合适的少数几个处理。这本 notebook 写做选择的路由器，以及专家装不下时怎么接纳。

## 为什么需要它

普通 Transformer 块里的前馈网络是稠密的：每个词元都要经过同一组参数。模型想变大，办法是把中间维加宽，所有参数都参与计算，每个词元的计算量也跟着涨。

MoE 换了个办法：把前馈网络拆成多个专家，每个词元只去少数几个。总参数可以变多，每个词元的计算量由“去几个专家”控制。换来的是三个新问题：

- **不知道该去哪个专家**。需要一个路由器给每个词元对所有专家打分，再挑出分数最高的 `K` 个。
- **挑出来的权重加起来不是 1**。3 个专家的概率是 `0.6652`、`0.2447`、`0.0900`，只留前两个，和是 `0.9100`。要重新归一化，才能当组合权重用。
- **专家装不下**。每个专家一轮最多接纳固定数量的分配。3 个词元都选了专家 `0`，容量是 `2`，就有 `1` 个分配被挤出去。

这本 notebook 写前两步，以及“装不下时谁被接纳”的规则。专家计算和合并的骨架已经给出，不用你写。

## 先认识几个词

| 词 | 人话解释 |
|:---|:---|
| 稠密 / 稀疏 | 稠密是每个词元都经过全部参数；稀疏是每个词元只经过少数几个专家 |
| 专家（expert） | 前馈网络拆出来的一份。本题里每个专家就是一个 `nn.Linear`，一共 `E` 个 |
| 路由器（Router）/ 路由分数 | 给每个词元对所有专家打分的小模块。本题是一个 `nn.Linear`，输出 `E` 个分数 |
| 完整概率 | 路由分数在专家维做 Softmax 的结果，`E` 个数加起来是 1 |
| Top-K | 只留概率最高的 `K` 个专家。要同时记下选中了谁（编号）和它们的概率（权重） |
| 重归一化 | 把留下的 `K` 个权重除以它们的和，让它们重新加起来等于 1 |
| 专家容量 / 溢出（overflow） | 一个专家一轮最多接纳的分配数。被选中的次数超过容量，多出来的部分叫溢出 |

## 核心思路

路由器的输入是形状 `[B, T, hidden_size]` 的隐藏状态，先被压平成每行一个词元。接着走四步：

```text
路由分数   scores  = gate(x)                     # [tokens, E]：每个词元对 E 个专家的打分
完整概率   probs   = softmax(scores, 专家维)      # [tokens, E]：每行加起来是 1           TODO 1
Top-K      weights, experts = topk(probs, K)    # 权重和编号都是 [tokens, K]            TODO 2
重归一化   weights = weights / weights 的行和    # [tokens, K]：每行重新加起来是 1        TODO 3
容量接纳   每个专家只接纳前 capacity 个分配       # 超出的部分记为溢出                    TODO 4
```

符号说明：`B` 是批量大小，`T` 是序列长度，`E` 是专家数（`num_experts`），`K` 是每个词元选几个专家（`top_k`）。路由器返回三样东西，各有用处：完整概率留着做统计，重归一化权重用来加权专家输出，专家编号决定词元去哪个专家。

Top-K 只是候选分配。每个专家一轮最多接纳固定数量的分配，超出的部分叫溢出，系统必须丢弃、重路由、排队或启用备用路径。所以路由概率正确，并不足以保证 MoE 可执行。`build_capacity_plan` 做的就是这一步，它返回接纳掩码（哪些分配被留下）、专家负载（每个专家被选了几次）和每个专家的溢出数。

下面用 1 个词元、3 个专家走一遍路由，再用 notebook 测试里的数据走一遍容量接纳：

```python
import torch

# 1) 路由：分数 → 完整概率 → Top-K → 重归一化
scores = torch.tensor([[2.0, 1.0, 0.0]])            # 1 个词元对 3 个专家的打分
probs = torch.softmax(scores, dim=-1)
weights, experts = torch.topk(probs, 2, dim=-1)      # K = 2
print(probs)
print(experts, weights, weights.sum())
print(weights / weights.sum())

# 2) 容量：3 个词元各选了 2 个专家，每个专家最多接纳 2 个
selected = torch.tensor([[0, 1], [0, 1], [0, 2]])
capacity = 2
for e in range(3):
    pos = torch.nonzero(selected == e, as_tuple=False)   # 选了专家 e 的 (词元, 第几个选择)
    print(e, pos[:capacity].tolist())                    # 只接纳前 capacity 个
load = torch.bincount(selected.flatten(), minlength=3)
print(load, (load - capacity).clamp_min(0))
```

```text
tensor([[0.6652, 0.2447, 0.0900]])
tensor([[0, 1]]) tensor([[0.6652, 0.2447]]) tensor(0.9100)
tensor([[0.7311, 0.2689]])
0 [[0, 0], [1, 0]]
1 [[0, 1], [1, 1]]
2 [[2, 1]]
tensor([3, 2, 1]) tensor([1, 0, 0])
```

第 1 部分：3 个概率加起来是 1。Top-K 选出专家 `0` 和 `1`，两个权重加起来只有 `0.9100`，除以这个和之后变成 `0.7311` 和 `0.2689`，重新加起来是 1。第 2 部分：专家 `0` 被 3 个词元选中，只接纳前两个，第 3 个词元的那次分配被挤掉。专家负载是 `[3, 2, 1]`，溢出是 `[1, 0, 0]`。

## 容易踩的坑

- **三个量混着用**：完整概率、Top-K 编号、重归一化权重不能互相替代。完整概率留着做统计，重归一化权重才用来组合专家输出。
- **留下 Top-K 之后没有重新归一化**：截取后的 `K` 个权重必须重新和为 1，要除以这 `K` 个选中概率自己的和。
- **选到了重复或不合法的专家**：每个词元恰好选 `K` 个互不相同的专家，编号落在 `[0, E)` 之内。`top_k` 必须在 1 到 `num_experts` 之间。
- **概率用了低精度**：统计使用 FP32，做 Softmax 之前先把路由分数转成 `float32`。
- **接纳顺序不稳定**：每个专家按稳定顺序接收前 `capacity` 个分配。截取的顺序变了，被挤掉的词元就变了。
