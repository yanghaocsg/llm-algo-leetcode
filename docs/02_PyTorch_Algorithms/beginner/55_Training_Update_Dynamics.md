## 一句话说清

一次训练更新到底把参数挪了多远，要由梯度大小、裁剪和学习率一起决定。这本 notebook 教你算出这几个量，并据此判断一次更新是数值失效、没有信号、被大幅压缩，还是可以继续观察。

## 为什么需要它

训练日志里能同时看到几个数：损失、梯度范数、学习率。单看其中一个，很容易判断错：

- 梯度范数（global norm）很大，不代表参数被推得很远，梯度裁剪（gradient clipping）可能已经把它缩小了。
- 梯度是有限值，不代表参数在动，它可能几乎没有移动。
- 更新记录一直稳定，不代表模型在变好，稳定只说明数值上没出问题。

比如日志里某一步梯度范数是 20，裁剪系数只有 0.02。原始梯度很大，但已经被压缩到原来的 0.02 倍，参数实际走了多远还要看学习率（learning rate）。

这本 notebook 把这些量连成一条链：梯度进来，经过合并、裁剪和学习率，变成参数的实际位移。再根据几个观察量，按固定顺序判断这次更新处在哪种状态。读完你要能分清“梯度很大”“更新很大”“模型能力提升”是三件不同的事。

## 先认识几个词

| 词 | 人话解释 |
|:---|:---|
| 全局范数（global norm） | 把一组梯度看成一个长向量的 L2 长度：各元素平方相加再开方。它描述梯度整体有多大 |
| 梯度裁剪（gradient clipping）与裁剪系数 `c` | 范数超过阈值 `m` 时，整组梯度乘上小于 1 的系数 `c` 等比缩小；没超过时 `c` 是 1 |
| 微批次（micro-batch） | 一次前向传播和反向传播实际处理的样本。几个微批次的梯度合并后，才形成一次有效更新 |
| SGD | 最简单的优化器：参数减去学习率乘以梯度。学习率记作 `η` |
| 参数位移（parameter delta）与相对更新比率（update ratio） | 参数位移 `Δθ` 是一次更新前后参数的变化量，它才是真正写回参数的量。它的长度除以参数的长度，就是相对更新比率 `ρ`，用来比较不同规模的参数组 |
| 有效目标数 | 一个微批次里真正参与损失计算的监督词元个数，记作 `n_i` |
| 有限值（finite） | 不是 NaN 也不是 Inf。出现非有限值，这次更新就不可信 |

## 核心思路

输入是各个微批次（micro-batch）算出的梯度。第一步，按有效目标数加权，把它们合并成一次更新用的梯度。第二步，算合并后梯度的全局范数，超过阈值就等比缩小。第三步，优化器按当前学习率把梯度变成参数位移（parameter delta），写回参数。输出是一份记录：损失、梯度范数、裁剪系数、参数位移、是否有限、成功更新步。notebook 的公式是：

```text
c = min(1, m / ||g||_2)          g~ = c * g          Δθ = -η * g~
ρ = ||Δθ||_2 / (||θ||_2 + ε)     g_eff = Σ_i (n_i / Σ_j n_j) * g_i
```

`g` 是合并后的梯度，`||g||_2` 是它的全局范数，`m` 是裁剪阈值，`c` 是裁剪系数，`g~` 是裁剪后的梯度，`η` 是这一步的学习率，`Δθ` 是参数位移，`θ` 是更新前的参数，`ε` 是防止除零的小正数，`ρ` 是相对更新比率（update ratio）。`g_eff` 是按 `n_i` 加权合并出的梯度，权重加起来等于 1。

用小数字把裁剪和合并各走一遍：

```python
import torch

g = torch.tensor([3.0, 4.0])                  # 原始梯度
norm = g.norm()                               # 全局范数
c = min(1.0, 2.5 / norm)                      # 裁剪系数：范数超过阈值 2.5 才缩小
clipped = c * g                               # 裁剪后的梯度
lr = 0.1
delta = -lr * clipped                         # SGD 的参数位移
theta = torch.tensor([1.0, 0.0])              # 更新前的参数
rho = delta.norm() / (theta.norm() + 1e-12)   # 相对更新比率
print("范数", norm, "裁剪系数", c, "裁剪后", clipped)
print("参数位移", delta, "位移长度", delta.norm(), "相对更新比率", rho)

parts = [torch.tensor([2.0, 4.0]), torch.tensor([8.0, 10.0])]   # 两个微批次的平均梯度
n = [1, 3]                                    # 各自的有效目标数
w = [count / sum(n) for count in n]           # 权重按目标数分摊，加起来等于 1
print("权重", w, "合并后的梯度", sum(p * wi for p, wi in zip(parts, w)))
print("直接平均（不对）", sum(parts) / 2)
```

```text
范数 tensor(5.) 裁剪系数 tensor(0.5000) 裁剪后 tensor([1.5000, 2.0000])
参数位移 tensor([-0.1500, -0.2000]) 位移长度 tensor(0.2500) 相对更新比率 tensor(0.2500)
权重 [0.25, 0.75] 合并后的梯度 tensor([6.5000, 8.5000])
直接平均（不对） tensor([5., 7.])
```

前两行：范数 5 超过阈值 2.5，梯度被缩到一半；再乘学习率 0.1，参数位移的长度是 0.25。后两行：第二个微批次的目标多，权重是 0.75，合并结果更靠近它；直接平均会把这个比例抹平。

拿到记录之后，判断顺序是固定的。先看是否有限，不是就记为 `blocked_nonfinite`。再看梯度范数是否为 0，是就是 `no_gradient`。再看裁剪系数是否远小于 1，是就是 `heavily_clipped`。再看参数位移是否接近 0，是就是 `low_parameter_motion`。都不是，记为 `observe_with_evaluation`：这次更新可以继续观察，模型能力要另外评测。

## 容易踩的坑

- **把梯度大当成更新大**：梯度范数高、裁剪系数远小于 1，说明原始梯度经常被压缩。要把阈值和学习率放在一起看。
- **把更新稳定当成能力提升**：`observe_with_evaluation` 只表示这次更新的数值链路说得通，模型能力要靠独立评测。
- **不等长微批次平均分权重**：权重必须按有效目标数来分，加起来等于 1。否则改变微批次的切分，同一逻辑批次的平均梯度就变了。
- **裁剪把小梯度放大了**：裁剪系数最大是 1。零梯度和阈值内的梯度都返回 1，不能放大原始信号。
- **非有限值没有最先拦截**：阈值、梯度范数或更新指标出现 NaN、Inf 时，没有可解释的比例，要直接拒绝或记为 `blocked_nonfinite`。
