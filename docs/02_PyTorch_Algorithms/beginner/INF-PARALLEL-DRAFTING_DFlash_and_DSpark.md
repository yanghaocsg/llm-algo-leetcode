## 一句话说清

让小模型一个接一个地猜后面的词，猜得越多等得越久。这本 notebook 讲一种一次把几个位置一起猜出来的办法，再用前一个词轻轻修正后一个，并把没把握的候选拦下来。

## 为什么需要它

投机解码里，草稿模型要连续猜出几个候选词元。普通的草稿模型是自回归的：猜第 2 个词元时必须先等第 1 个猜完，因为它要把第 1 个词元当输入。候选越长，这条串行的路就越长。

DFlash 的做法是不等了：让草稿模型跑一次前向传播，同时给出后面好几个位置的词表分数，每个位置各取最高分的词元，拼成一个候选块。代价是，后面那些位置在打分时并不知道前面真正选了什么词元，候选质量可能越往后越差。

DSpark 在这上面补两件事：

- 轻量的顺序修正。选定一个位置的词元后，把这个词元变成一个很短的状态向量，再投影成一份加在下一个位置分数上的偏置。它比重新跑一遍草稿模型便宜，但让后面的位置知道前面选了什么。
- 用置信度控制预算。每个候选位置带一个置信度，从第一个位置起，连续够高的才送去验证。第一个就不够高，就一个都不送，退回普通的解码。

这本 notebook 用 Python 列表把这三步写出来：并行取候选、低秩投影、选连续的置信前缀。

## 先认识几个词

| 词 | 人话解释 |
|:---|:---|
| 自回归草稿 | 一个接一个猜候选的草稿方式：后一个位置要等前一个候选出来才能打分 |
| 候选块 | 一次前向传播同时给出的多个候选词元，按位置排成一列 |
| 并行主干 | 一次给出候选块里每个位置基础词表分数的那部分 |
| 秩（rank） | 状态向量的长度，记作 `r`。`r` 远小于词表大小时，存和算都省 |
| 前驱状态、投影 `P` | 前一个候选词元查表得到长度为 `r` 的状态向量，再乘上 `r` 行、`V` 列的矩阵 `P`，得到长度为 `V` 的词表偏置。`V` 是词表大小 |
| 置信度 | 每个候选位置自带的 0 到 1 之间的数，表示这个候选有多大把握。低于阈值就不再往后送 |
| 验证预算 | 本轮真正送去给目标模型验证的候选个数，只能是连续通过的那一段 |

## 核心思路

三个 TODO 对应三个小函数，都用 Python 列表完成。

① 并行候选（DFlash）。输入 `block_logits` 是一个列表的列表：每个位置一行，一行是该位置的词表分数。每一行各自取分数最大的下标，就是候选块。各行互不影响。

② 低秩修正（DSpark）。对候选块里的每个位置，按顺序做下面几步：

```text
e      = markov_embeddings[前一个词元]      # 前驱状态：长度为 r 的向量
b[v]   = e[0] * P[0][v] + ... + e[r-1] * P[r-1][v]    # 词表偏置，v 遍历词表
修正分数 = 基础分数 + b
查不到前一个词元的状态 → 偏置取全 0
```

在修正后的分数里取最大，作为这个位置的候选；它又成为下一个位置的前驱，所以修正必须按位置顺序做。

③ 置信预算。输入是每个位置的置信度、阈值和上限 `max_tokens`。只看前 `max_tokens` 个位置，从第一个数起，置信度不低于阈值就加一；遇到第一个低于阈值的位置就停，后面的即使置信度高也不算。数出来的长度就是本轮送去验证的候选数。骨架里的 `build_draft_record` 用它截出 `verify_tokens`，预算为 0 时把 `fallback_to_decode` 设为真。

下面是测试里的数字，词表大小为 2，秩为 1：

```python
block_logits = [[0.4, 0.6], [0.7, 0.3], [0.6, 0.4]]     # 3 个位置的基础分数，词表大小为 2
print([row.index(max(row)) for row in block_logits])     # DFlash：每个位置独立取最高分

embeddings = {9: [1.0], 0: [-1.0], 1: [1.0]}             # 词元到低维状态的查表，秩为 1
projection = [[0.5, -0.5]]                               # 投影矩阵：1 行（秩）× 2 列（词表）

previous, candidates = 9, []                            # 9 是 anchor_token：第一个位置用它当前驱来查状态
for row in block_logits:
    latent = embeddings[previous]                       # 前驱词元的低维状态
    bias = [sum(latent[i] * projection[i][v] for i in range(1)) for v in range(2)]
    corrected = [score + delta for score, delta in zip(row, bias)]   # 基础分数 + 偏置
    previous = corrected.index(max(corrected))
    candidates.append(previous)
print(candidates)

prefix = 0
for confidence in [0.9, 0.8, 0.3, 0.95]:                # 逐位置置信度
    if confidence < 0.5:                                # 阈值 0.5，上限 4 个
        break
    prefix += 1
print(prefix)
```

```text
[1, 0, 0]
[0, 1, 0]
2
```

第一行是只用并行主干：每个位置各取最高分，得到 `[1, 0, 0]`。第二行是加上顺序修正：传进来的 `anchor_token` 是 9，它是第一个位置的前驱，状态是 `[1.0]`，投影成偏置 `[0.5, -0.5]`，第一个位置的基础分数 `[0.4, 0.6]` 加上后变成 `[0.9, 0.1]`，候选变成 0。这个 0 又作为前驱查到状态 `[-1.0]`，偏置变成 `[-0.5, 0.5]`，第二个位置于是选了 1；第三个位置再用 1 当前驱，选回 0。第三行是置信预算：前两个位置过了 0.5，第三个是 0.3 没过，就停在这里，虽然第四个是 0.95。

目标模型仍然负责接受或拒绝，草稿的置信度不能替代验证。

## 容易踩的坑

- **让一个位置读到相邻位置的候选**：DFlash 的候选必须位置独立。修改某一位置的分数只能改变该位置的候选，不能传播到其他位置。
- **偏置维度和词表对不上**：前驱状态的长度必须等于 Markov 秩 `r`，投影的每一行必须覆盖完整词表 `V`，否则报错。
- **给未知前驱编了一个偏置**：查不到前驱词元的状态时，应返回全 0 的偏置，不引入任意的修正。
- **跳过低置信位置继续往后数**：验证预算只包含从首位置开始连续通过阈值的候选，第一个低置信位置截断整个后缀。
- **把置信度当成验证**：目标模型仍负责接受或拒绝。第一个位置就低于阈值时预算为 0，不提交草稿候选，回退普通 Decode。阈值和每个置信度都必须在 0 到 1 之间。
