## 一句话说清

GPTQ 和 AWQ 是两种把权重压到 4 位的方法。它们都会先看一批真实输入在这一层长什么样，再判断哪些权重的误差更要紧。这本 notebook 在 CPU 上写出它们的简化版。

## 为什么需要它

把权重压到 4 位，比 8 位粗糙得多：题目默认 `bits = 4`，整数码只能取 -7 到 7。每个权重只能落到这几个格子上，误差躲不掉。

最直接的做法是把每个权重各自四舍五入到最近的格子。它对所有权重一视同仁，但权重误差的影响并不一样：

- 权重乘的那个输入通道数值很大：同样大小的权重误差，会把这一层的输出带偏很多。
- 权重乘的那个输入通道几乎总是 0：这里的权重误差几乎不影响输出。

GPTQ 的思路是用校准激活算出每个输入通道的敏感度，用它衡量权重误差对层输出的影响。AWQ 的思路是用激活幅度找出显著通道，重点照顾这些通道对应的权重。这本 notebook 只做 CPU 上的教学代理：观察敏感度、标记显著通道、生成分组缩放因子。完整的 GPTQ 误差补偿和 AWQ 缩放搜索，由成熟框架执行。

## 先认识几个词

| 词 | 人话解释 |
|:---|:---|
| 校准激活（calibration activation） | 让一批有代表性的样本流过模型时，目标层实际收到的输入 |
| 通道均方根（root mean square，RMS） | 每个输入通道上激活值的典型大小，越大说明这个通道越常出现大数值 |
| Hessian 对角代理 | 用每个通道的“平方平均值”来近似：权重误差落在哪个通道，对层输出影响更大 |
| 显著通道（salient channel） | 激活幅度大的输入通道，AWQ 重点照顾它们对应的权重 |
| 权重误差与层输出误差 | 前者是恢复权重和原权重差多少，后者是这一层最终输出差多少，两者不一定成正比 |
| 分组（group） | 沿输入方向把权重切成固定长度的小段，每段共用一个缩放因子 |
| 量化产物（artifact） | 量化后交出去的整套东西：权重文件，加上缩放因子、位宽、分组大小等记录 |

## 核心思路

输入是浮点权重 `W` 和校准激活 `X`。骨架已经负责分组循环、恢复、加权误差和产物清单，你要补的是三处：

1. 收集统计：对每个输入通道求激活的平方平均值，作为 Hessian 对角代理；再开平方，得到激活均方根。
2. 标记显著通道（只有 `method` 是 `"awq"` 时）：在每个分组内按激活均方根挑出前几名，写进布尔掩码。
3. 算分组缩放因子：每个分组里没被保护的权重，用绝对最大值除以 `qmax`，再把权重四舍五入成整数码。

输出是量化后的权重状态，既能恢复成浮点近似权重，也能给出一份产物清单。notebook 用下面几个式子说明“为什么有的误差更要紧”，这里是纯文本版：

```text
Y = X * W^T                                线性层的输出，X 是校准输入，形状 [N, d]
dY = X * dW^T                              权重误差 dW 造成的层输出误差
H = X^T * X / N                            输入方向的二阶代理，也叫 Hessian 近似
(1 / N) * ||dY||^2 = tr(dW * H * dW^T)     同样大小的 dW，落在不同通道，层输出误差不同
a_j = sqrt(mean_n(X[n, j]^2))              第 j 个输入通道的激活均方根，也是 H 对角线的平方根
I_j = a_j * ||W[:, j]||                    教学显著性代理：激活幅度乘上权重列的大小
```

符号说明：`N` 是样本数，`d` 是输入通道数，`dW` 是恢复权重和原权重之差，`dY` 是对应的层输出误差，`tr` 是矩阵的迹，`a_j` 是第 `j` 个通道的激活均方根，`I_j` 是第 `j` 个通道的显著性得分。

下面用 4 个样本、3 个输入通道走一遍：

```python
import torch

print(2 ** (4 - 1) - 1)                                   # bits = 4 时的 qmax

X = torch.tensor([[1.0, 0.0, 5.0], [1.0, 0.0, -5.0],
                  [-1.0, 0.0, 5.0], [-1.0, 0.0, -5.0]])   # 校准激活：4 个样本、3 个输入通道
hessian_diag = X.square().mean(dim=0)                     # Hessian 对角代理
print(hessian_diag, hessian_diag.sqrt())                  # 激活均方根

dWa = torch.tensor([0.1, 0.0, 0.0])                       # 两个候选的权重误差，大小相同
dWb = torch.tensor([0.0, 0.0, 0.1])
for dW in (dWa, dWb):
    dY = X @ dW                                           # 层输出误差（一个输出通道）
    print(round(float(dY.square().sum() / 4), 4), round(float((dW.square() * hessian_diag).sum()), 4))

print(torch.topk(hessian_diag.sqrt(), k=1).indices)       # 三个通道里最显著的 1 个
```

```text
7
tensor([ 1.,  0., 25.]) tensor([1., 0., 5.])
0.01 0.01
0.25 0.25
tensor([2])
```

读五处：

- 第一行：`bits = 4` 时 `qmax` 是 7。
- 第二行：三个通道的平方平均值是 1、0、25，均方根就是开平方。
- 第三、四行：两个权重误差一样大，落在通道 2 上的那个，层输出误差是 0.25，另一个只有 0.01。每行里直接按 `dW` 和 `H` 的对角线算出的数，和先算 `dY` 再平方求和的结果一样。
- 第五行：按均方根排序，最显著的通道是下标 2。

对角代理忽略了通道之间的相关性，在这里只用它说明“为什么有的误差更要紧”。

## 容易踩的坑

- **把教学代理当成真实算法或压缩产物**：CPU 的 `gptq` 选项只是“逐组直接舍入 + 敏感度评价”，没有做逐步量化和误差补偿，评分变化不能解释成算法改善了码值。`awq` 选项把被保护的位置直接留成浮点值（真实 AWQ 靠缩放搜索保护通道），多存了旁路和掩码，整数码也没有打包，不能直接充当压缩产物。
- **两个统计量的通道对不上**：先把校准激活展平成“样本 × 输入通道”，再沿样本那一维求平均。两者的形状都是 `[in_features]`，均方根必须等于对角代理开平方。
- **保护跨了分组**：显著性排序只在当前分组内做，`topk` 给出的是组内下标，直接写进这一组的掩码。
- **`gptq` 分支也生成了保护位**：只有 `method` 是 `"awq"` 时才标记保护通道，`gptq` 分支的掩码应该全是 `False`。
- **缩放因子把被保护的权重也算进去了**：缩放因子按未保护的权重算。全零分组和不足一组的尾组，也要得到有限的正缩放因子。
