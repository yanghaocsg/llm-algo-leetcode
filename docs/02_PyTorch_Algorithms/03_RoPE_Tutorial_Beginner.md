## 一句话说清

RoPE 是让大模型知道“谁在前、谁在后”的办法：按每个词元的位置，把它的查询向量和键向量转动一个角度，注意力比较它们时就能感觉到两个词元相距多远。

## 为什么需要它

注意力靠比较词元之间的相似度来决定“看谁”，而这个比较本身和顺序无关。三个词元 `A`、`B`、`C`，排成 `A B C` 还是 `C B A`，`A` 和 `B` 的相似度是同一个数。不补上位置信息，模型看到的更像一袋词元。补位置时又有两个坑：

- **位置写得太死**。位置处理得太死，模型又很难泛化到更长的上下文。RoPE 没有走“给词元额外加一个位置向量”这条路，而是把位置写进查询向量和键向量的旋转里。
- **以为调大长度配置就够了**。训练长度之外继续用原来的频率，模型会遇到训练中没有充分覆盖的相位组合。只把 `max_position_embeddings` 调大，并不会自动获得可靠的长上下文能力。

RoPE 的思路是：按位置把查询和键各转一个角度，两个词元做内积（对应位置相乘再相加，得到一个数）的结果，就带上了“相差多远”的信息。这本 notebook 只做基础的两步：造角度表，把旋转用到查询和键上。更长上下文的扩展方案只在 Step 3 里比较，要另外评测。

## 先认识几个词

| 词 | 人话解释 |
|:---|:---|
| 查询 / 键 / 值（Query, Q / Key, K / Value, V） | 注意力里的三个向量。每个词元用自己的 Q 和别的词元的 K 做内积，决定关注谁；V 是被取走的内容。RoPE 只转 Q 和 K，不动 V |
| 头维度 `D` / 通道对 | `D` 是每个注意力头里向量的长度（`head_dim`）。相邻两个数配成一对，一共 `D/2` 对，每对是一个二维平面 |
| 旋转 / 复数（complex） | 把一个点绕原点转一个角度，长度不变。代码里把一对数 `(a, b)` 写成复数 `a + b j`，乘上长度为 1 的复数就是转一次 |
| 频率（`inv_freq`）/ 角度 | 每个通道对一个频率。位置 `m` 的角度是 `m × 频率`；频率高的通道对，位置往后走时转得快。notebook 里说的“相位”就是角度 |
| 模长 | 向量的长度。旋转只改变方向，所以旋转前后每个通道对的模长不变 |
| 广播（broadcast） | 把 `[S, D/2]` 的角度表变成 `[1, S, 1, D/2]`，让它自动作用到所有批次和所有注意力头上 |
| 长度外推 | 训练时序列最长到某个长度，推理时要用更长的序列。这本 notebook 不写这部分代码 |

## 核心思路

RoPE 分两步。

第一步是造一张角度表 `freqs_cis`。输入是头维度 `D`、序列长度 `S`（代码里叫 `end`）和基频 `theta`，输出是形状 `[S, D/2]` 的复数表：

```text
inv_freq[i]      = 1 / theta^(2i / D)          # 第 i 个通道对的频率
angles[m, i]     = m * inv_freq[i]             # 位置 m 在第 i 个通道对上要转的角度
freqs_cis[m, i]  = cos(angles[m, i]) + j * sin(angles[m, i])    # 长度为 1 的复数
```

符号说明：`i` 是通道对的编号，从 `0` 到 `D/2 - 1`；`m` 是位置，从 `0` 开始；`j` 是虚数单位。位置 `0` 的角度全是 `0`，所以表的第一行全是 `1 + 0j`，也就是不旋转。频率从高到低：编号小的通道对转得快，编号大的转得慢。

第二步是把表用到 Q 和 K 上。它们的形状是 `[B, S, H, D]`，`H` 是注意力头数。把最后一维相邻的两个数看成一对，写成复数 `a + b j`。每个位置 `m` 的 Q 和 K 都乘上表的第 `m` 行，再拆回两个实数。表先广播成 `[1, S, 1, D/2]`，对所有批次和注意力头通用。输出的形状和数据类型都和输入一样。

为什么这样就有了位置？两个位置 `m`、`n` 在同一个通道对上相差的角度是 `(m - n) * inv_freq[i]`，只和它们相差几个位置有关。

下面用 `D = 4` 把两步各算一遍。第二部分为了好算，设成每前进一个位置转 90 度：

```python
import torch

# 1) 角度表：D = 4（2 个通道对），位置 0 到 2，theta 取默认的 10000
pair_indices = torch.arange(0, 4, 2, dtype=torch.float32)
inv_freq = 1.0 / (10000.0 ** (pair_indices / 4))
print(inv_freq)
angles = torch.outer(torch.arange(3, dtype=torch.float32), inv_freq)
print(angles)
print(torch.polar(torch.ones_like(angles), angles)[0])

# 2) 旋转：为了好算，设成每前进一个位置转 90 度
pos = torch.arange(5, dtype=torch.float32)
rot = torch.polar(torch.ones(5), pos * 1.5707964)
v = torch.view_as_real(rot)            # 位置 m 上，向量 (1, 0) 转完之后的样子
print(v[1] @ v[3], v[2] @ v[4])         # 相隔 2 个位置的两个向量的内积
x = torch.view_as_complex(torch.tensor([[3.0, 4.0]]))
print(torch.view_as_real(x * rot[1]), x.abs())
```

```text
tensor([1.0000, 0.0100])
tensor([[0.0000, 0.0000],
        [1.0000, 0.0100],
        [2.0000, 0.0200]])
tensor([1.+0.j, 1.+0.j])
tensor(-1.) tensor(-1.)
tensor([[-4.0000,  3.0000]]) tensor([5.])
```

第 1 部分：两个通道对的频率是 `1.0` 和 `0.01`，位置 `2` 的角度就是 `2.0` 和 `0.02`。第 2 部分：位置 `1` 和位置 `3` 相差 180 度，内积是 `-1`；位置 `2` 和位置 `4` 也相差 180 度，内积同样是 `-1`。绝对位置不同，只要相差的位置数相同，内积就相同。向量 `(3, 4)` 转完变成 `(-4, 3)`，长度还是 `5`。

## 容易踩的坑

- **头维度是奇数**：`dim` 必须是正的偶数，否则两两配对配不完。`precompute_freqs_cis` 和 `apply_rotary_emb` 遇到奇数维度都会直接报错。
- **角度表长度不够**：频率表的长度必须覆盖当前序列的位置。`reshape_for_broadcast` 要求表的形状等于 `(序列长度, D/2)`，对不上就报错。
- **没有把相邻两个数配成一对**：最后一维相邻的两个数才是同一对。先 `.float()`，再每两个数一组变成复数，批次、序列与注意力头轴不动。
- **输出的模长或数据类型变了**：单位复数乘法只改变方向，不改变模长。中间用 FP32 复数计算，最后要转回输入的 `dtype`。
- **把 RoPE 当成可见范围或长度的保证**：它只旋转 Q/K，不决定哪些历史位置可见，也不保证训练长度外的任务质量。
