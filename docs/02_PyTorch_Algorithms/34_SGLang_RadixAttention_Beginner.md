## 一句话说清

很多请求的开头相同，重复算这些开头很浪费。这本 notebook 教你用一棵树把登记过的开头串起来，新请求沿着树找最长的一段直接复用，剩下的再算。

## 为什么需要它

真实服务里，请求常常不是彼此独立的：多轮对话每一轮都带着之前的历史，智能体和工具调用带着很长的系统提示词。这些开头一模一样，如果每个请求都重新算一遍，KV Cache 会被重复占用，第一个词元也要等得更久。

前缀缓存解决的就是这个问题：把算过的开头留下来，后面开头相同的请求直接复用，只算从第一个不同词元开始的后缀。24 号 notebook 把每个前缀当成一个完整对象，逐个和请求的开头比较。

这本 notebook 换了一种组织方式，叫基数树（Radix Tree）：把登记过的词元路径串成一棵树，开头相同的部分只保留一条共享路径，到第一个不同的词元才分成两支。RadixAttention 用它做索引，组织可复用的前缀状态。

你要在 CPU 上实现这棵树的查找逻辑：新路径怎样插进去、怎样沿树找最长命中、怎样把请求拆成两段。

## 先认识几个词

| 词 | 人话解释 |
|:---|:---|
| 基数树（Radix Tree） | 一种按词元路径组织前缀的树。连续、没有分叉的一段词元压成一条边，分叉的地方才分成两支 |
| RadixAttention | 用基数树做索引来组织可复用的前缀状态。树负责查找，缓存管理还要保证状态驻留和安全引用 |
| 公共前缀 | 多个请求开头相同的词元序列 |
| 压缩边 | 树里的一条边，上面存着一段连续的词元，比如 `[1, 2]`，而不是单个词元 |
| 终止节点（terminal） | 一条完整登记过的路径在这里结束。只有走到终止节点，这段才算可复用 |
| 最长公共前缀（LCP） | 两段词元序列从开头开始连续相同的最长长度 |
| 未命中后缀 | 从第一个不一致的词元开始，请求剩下的部分，要继续预填充 |

## 核心思路

树里的每个节点是 notebook 里的一个 `TreeNode`：`key_tokens` 是这条边上的词元，`children` 是子节点，`terminal` 表示有没有完整路径在这里结束，`kv_cache_ptr` 是留给真实缓存的占位。

新请求进来，notebook 沿着树走：

- 找边：从根出发，找第一条词元和请求当前词元相同的子边。
- 比词元：用最长公共前缀逐个比较，一条边完整走过了才能继续往下。
- 记命中：只有走到终止节点，才把当前位置记成可复用的长度。
- 拆分：按命中长度把请求切成可复用前缀和未命中后缀。

插入新路径时，如果和已有的一条边只重叠了一部分，这条边要分裂。下面是 notebook Step 2 的例子：

```text
登记 [1, 2, 3]：    root ── [1, 2, 3]（终止）
再登记 [1, 2, 4]：  root ── [1, 2] ──┬── [3]（终止）
                                     └── [4]（终止）
```

Step 3 把命中长度写成一个式子：

```text
H = max( {0} ∪ { |c| : c 属于 C，且 c = P[:|c|] } )
```

`C` 是所有完整登记对象的集合，`P` 是请求的词元序列，`|c|` 是对象 `c` 的词元数，`P[:|c|]` 是请求开头同样长度的片段，`H` 是可返回的命中长度。意思是：在和请求开头完全一致的登记对象里取最长的，一个也没有就是 0。如果再登记 `[1, 2]`，`[1, 2]` 这个节点自己也成了终止位置。

下面用代码走一遍查找，数字取自 notebook 的 Step 2、Step 3 和测试：

```python
tree = [[1, 2], False, [[[3], True, []], [[4], True, []]]]   # [边上的词元, 是否终止, 子节点列表]

def lcp(a, b):                             # 最长公共前缀长度，遇到第一个不同就停
    n = 0
    for x, y in zip(a, b):
        if x != y:
            break
        n += 1
    return n

def match(children, tokens):               # 从这些子边往下，最多能命中多长
    for edge, end, kids in children:
        n = lcp(edge, tokens)
        if 0 < n == len(edge):             # 开头相同，而且这条边完整走过了
            deeper = match(kids, tokens[n:])
            return n + deeper if deeper else (n if end else 0)
    return 0

print(lcp([1, 2, 3], [1, 2, 4]), lcp([7, 8], [7, 8, 9, 10]))
print(match([tree], [1, 2, 9]), match([tree], [1, 2, 3]), match([tree], [1, 2, 4]))
tree[1] = True                             # 再登记 [1, 2]：这个节点自己也成了终止位置
print(match([tree], [1, 2, 9]))
```

```text
2 2
0 3 3
2
```

第一行是最长公共前缀，两组都是 2 个词元相同。第二行：请求 `[1, 2, 9]` 走过共享边 `[1, 2]`，但 `[1, 2]` 不是终止位置，命中长度是 0；`[1, 2, 3]` 和 `[1, 2, 4]` 都能走到终止节点，命中 3 个词元。第三行：登记 `[1, 2]` 以后，`[1, 2, 9]` 才能命中 2 个词元。

notebook 特意说明：最长公共前缀只说明词元是否相同，不能证明对应的状态已经保存。`kv_cache_ptr` 只是占位，不指向真实的 K/V。

## 容易踩的坑

- **分裂时弄丢旧边的状态**：把公共前缀提升为共享父边后，旧边的子节点、终止状态和缓存引用要跟着旧后缀走，新后缀放到另一个分支。
- **最长公共前缀越界**：返回长度不能超过任一输入序列，完全一致时等于较短序列的长度。
- **把共享路径当成可复用**：只有完整走过已登记路径并到达终止节点，才更新可复用长度。不完整边和非终止节点不算。
- **拆分后两段对不上原输入**：可复用前缀和未命中后缀重新拼接后，必须等于原始请求。空输入和零命中时也要能安全返回。
