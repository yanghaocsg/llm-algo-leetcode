# 20. Llama3 Block 综合项目：把 Triton 注意力接进真实 Block — 小白讲解

> 对应 notebook：[`20_Triton_Llama3_Block_Project.ipynb`](./20_Triton_Llama3_Block_Project.ipynb)

## 一句话总结
把前面写好的 Triton 因果注意力塞进一个带 RMSNorm、Q/K/V 投影、RoPE、残差和 SwiGLU MLP 的 LLaMA 风格解码块里，学会"局部替换组件"时怎样保证布局、因果关系和误差归因都不出岔子。

## 为什么需要它：痛点是什么
单测里和参考对得准的注意力 kernel，接进真实 Block 后未必还对：投影出来的张量要拆头、要连续化，注意力输出要按原顺序拼回去，任何一步接错都可能"形状完全正确、数值完全错误"，而且这种 bug 藏在残差和 MLP 后面很难看出来。这就像换了台性能很好的新机器插进流水线：机器本身测试合格（kernel 单测通过）不够，还要确认进料方向没接反（Q/K 没交换）、出口物料回到原来的工位（合头顺序正确），整条线的成品才能合格（Block 输出一致）。朴素做法"整个 Block 都用 PyTorch"没有替换风险，但也就永远享受不到手写 kernel 的收益——局部替换正是工程上真正会发生的事。

## 核心问题
- 拆头/合头时，怎样保证每个位置的特征进对了头、又按原顺序拼回去？
- 替换的边界在哪：换成 Triton 注意力时，哪些东西必须保持不变（因果可见关系、分数缩放）？
- 最终输出有微小差异时，怎么判断问题出在注意力还是别处？

## 解决思路：一步步看懂
1. **Block 数据流**。输入隐状态按 batch-first（批量在首维）排列 [B,S,D]，例如 [2,73,256]：2 条序列、每条 73 个位置、每位置 256 个特征。经过 RMSNorm 和 Q/K/V 投影后拆成 4 头、每头 64 维，变成注意力的 [B,4,73,64]；RoPE 只作用于 Q 和 K；注意力输出合并回 [2,73,256]，再走输出投影、残差和 SwiGLU MLP。
2. **拆头（TODO 1）**：把每个位置的 D 个特征按相邻 d 个一组分成 H 份，再把头维交换到序列维之前，得到连续的 [B,H,S,d]。关键在保留"每个位置内部原有的特征分组"——不能直接把存储解释成 [B,H,S,d]。
3. **适配与调用（TODO 2/3）**：共享内核要求三路 Q/K/V 连续，所以 `q_ready, k_ready, v_ready` 三路各自整理（连续的可以直接复用），数值、类型、设备和 Q/K/V 顺序都不变；然后把同一组 Q/K/V 交给 `triton_flash_attention` 并保持因果条件——当前位置只读自身和更早的键值。注意 SDPA（Scaled Dot Product Attention，缩放点积注意力的 PyTorch 接口）只是个会按环境选后端的接口，不等于某个固定 kernel，这里仅作参考实现。
4. **合头（TODO 4）**：先把 [B,H,S,d] 转回 [B,S,H,d]，再按原顺序把 H×d 拼成 D，这样输出投影的每一列接到的还是原来那个头的分量。拆头和合头是互逆操作，两处都错反而可能形状上"看起来没事"，所以要分别独立测试。
5. **误差归因**：两个模型用相同权重和输入，只切换注意力实现。分别比较 Q/K/V、局部注意力输出、恢复布局和完整 Block 输出，就能定位差异出在哪一层；再用"扰动未来位置、历史前缀输出必须不变"验证因果关系，用 CUDA 事件确认真的走了目标设备路径。本页只核对前向推理，用于训练还需另行确认反向。

## 关键概念速查表
| 术语 | 大白话解释 |
|---|---|
| batch-first | 批量维放在张量首维 [B,S,D] 的布局 |
| 拆头/合头（split/merge heads）| 特征维 D 拆成 H×d 供注意力使用，算完再拼回去 |
| RoPE | 旋转位置编码，只作用于查询和键 |
| 因果（causal）| 当前位置只能看见自己和更早的位置 |
| SDPA | PyTorch 缩放点积注意力接口，按环境选后端，非固定 kernel |
| 残差（residual）| 把子层输出加回输入的捷径连接 |
| SwiGLU | 带门控的前馈网络结构（gate/up/down 三个投影） |
| 连续化（contiguous）| 把非连续视图整理成内存里挨着存的新张量 |

## 小白常见疑问
- **Q：形状都对，为什么还要专门查布局？** 用错维度拼接（比如合头时头的顺序乱了）张量形状照样合法，但输出投影的每一列读到的是别的头的分量——数值悄悄全错。
- **Q：为什么三路 Q/K/V 都要连续化，不能只处理一路？** 共享内核按连续布局寻址；测试会故意传入三路都非连续的视图，漏掉任何一路都会在读内核前被抓。
- **Q：局部注意力和完整 Block 输出都查，是不是重复？** 不重复：局部对了说明 kernel 和适配没问题；完整 Block 还包含投影、残差和 MLP 的误差传播，两处对照才能把差异归因到具体某一层。
