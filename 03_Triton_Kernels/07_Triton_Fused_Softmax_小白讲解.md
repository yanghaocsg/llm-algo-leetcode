# 07. Triton 融合 Softmax — 小白讲解

> 对应 notebook：[`07_Triton_Fused_Softmax.ipynb`](./07_Triton_Fused_Softmax.ipynb)
> NPU 版：[`07_Triton_Fused_Softmax_NPU.ipynb`](./07_Triton_Fused_Softmax_NPU.ipynb)

## 一句话总结

这个 notebook 教你在**一个** Triton kernel 里完成数值稳定的按行 Softmax：减最大值、取指数、求和、归一化一次做完，不把中间结果写回显存。

## 为什么需要它：痛点是什么

Softmax 要把一行分数变成和为 1 的概率。拿 `[1000, 1001, 1002]` 来说，直接算 $e^{1000}$ 会直接溢出（float 的上限只有约 $e^{88}$）。教科书解法是先减去行最大值再取指数，但用朴素 PyTorch 实现就得串四步：`x - x.max()` → `exp` → `sum` → `div`，每一步都产生一个中间张量，写回显存再读出来。这就像做菜时每切完一刀就把菜装盒、放进冰箱、再拿出来切下一刀——刀工没变多，来回搬运却全是白费。

"融合（fuse）"就是把这四刀并在一次 kernel 调用里连续完成，中间量只待在寄存器里。

## 核心问题

- 为什么必须先减行最大值？减完概率为什么不变？
- 一次 kernel 内，一整行怎样共享最大值和指数和这两个归约结果？
- 行宽不是 2 的幂时，补齐位置填什么才不会污染结果？

## 解决思路：一步步看懂

1. **减最大值：数学上无损，工程上保命。** 公式 $p_i=\dfrac{e^{x_i-m}}{\sum_j e^{x_j-m}}$，其中 $m$ 是本行最大值。分子分母同乘 $e^{-m}$，概率不变；但指数的输入被压到全不大于 0，最大那个恰好是 $e^0=1$，永远不溢出。`[1000,1001,1002]` 减 1002 变 `[-2,-1,0]`。

2. **一个 Program 包一行，两次归约。** 归约（reduction）就是把多个数合并成一个数。第一次归约求行最大值 $m$，减完取指数后，第二次归约求指数和 $s$，最后每列除以同一个 $s$：`[e^-2, e^-1, 1]` → 概率约 `[0.0900, 0.2447, 0.6652]`。这些依赖关系（指数依赖最大值、归一化依赖指数和）不能省略，融合只是让它们在一次调用内完成。

3. **补齐位置必须填负无穷。** 行宽 3、逻辑块宽 4 时，多出的位置也会参与归约。参考实现的加载用 `other=-float("inf")"`：负无穷减去有限的行最大值还是负无穷，指数恰好为 0，既不抬高最大值、也不增加分母。反例：全负行 `[-2,-2,-2]` 若把补齐位错填成 0，分母就多出 $e^{2}$ 一份贡献，三个概率不再各是 $1/3$——这是 notebook 里最漂亮的陷阱。

4. **核心四行（参考实现）：**

   ```python
   row_max = tl.max(row, axis=0)          # 第一次归约：本行最大值
   safe_row = row - row_max               # 整行平移，指数输入全 <= 0
   numerator = tl.exp(safe_row)           # 补齐位是 -inf，指数恰为 0
   denominator = tl.sum(numerator, axis=0) # 第二次归约：本行指数和
   softmax_output = numerator / denominator # 每列除以同一个分母
   ```

5. **精度与写回分开。** 加载后升到 FP32 做减法、指数、求和，写回时按输入类型（FP16/FP32）存，并用 `mask = columns < n_cols` 屏蔽补齐列。启动器里 `block_size = triton.next_power_of_2(columns)`，块宽小于 2048 用 4 个 warp，否则 8 个。

## 关键概念速查表

| 术语 | 大白话解释 |
|---|---|
| Program | 一个工人线程块，本节一个 Program 负责一整行 |
| 融合（fusion） | 多步计算合并进一次 kernel 调用，中间量不落显存 |
| 归约（reduction） | 把多个值合并成一个值，如 max、sum |
| mask | 访问掩码，标记哪些位置是真的、哪些是补齐的 |
| BLOCK_SIZE | 逻辑块宽，必须取 2 的幂，行宽不足就补齐 |
| `other=-inf` | 补齐位置的填充值，让它在 max 和 exp 后都"隐形" |
| 数值稳定 | 通过减最大值避免大数指数溢出 |
| FP32 / FP16 | 32 位/16 位浮点；中间算用 FP32，存储可回 FP16 |

## 小白常见疑问

- **Q：为什么不直接 `exp(x)/sum(exp(x))`？** 大分数一取指数就溢出成 inf，结果全 NaN。减最大值是数值稳定的标准做法。
- **Q：补齐位置填 0 行不行？** 不行。0 会参与 max 和 sum 归约：全负行里它成了假最大值，指数和里还多出贡献。负无穷在两处都恰好无害。
- **Q：融合后归约消失了吗？** 没有。依赖关系还在，只是中间量在同一次调用内被消费，不再显式建立供后续 kernel 读取的中间张量。
- **Q：一行特别宽怎么办？** 整行装载让单个 Program 的资源需求随行宽增长，本练习限制行宽不超过 4096；更宽的行需要分块方案。

## 动手验证：怎么知道自己做对了

正确性测试把 Triton 输出与 `torch.softmax(x, dim=1)` 用 `torch.testing.assert_close` 对照（FP16 容差 1e-3、FP32 容差 1e-5），并额外检查：概率非负且不超 1、每行和为 1、输出形状/类型/设备一致、输入未被修改。用例覆盖单元素、非 2 次幂行宽（3、257）、常量行、以及整行 ±1000 大幅平移后结果不变。性能上用 `triton.testing.do_bench` 在 1024×1024 输入上对比 `torch.softmax` 与 `triton_softmax`。
