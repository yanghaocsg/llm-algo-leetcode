# 10. Triton 融合旋转位置编码（RoPE）— 小白讲解

> 对应 notebook：[`10_Triton_Fused_RoPE.ipynb`](./10_Triton_Fused_RoPE.ipynb)
> NPU 版：[`10_Triton_Fused_RoPE_NPU.ipynb`](./10_Triton_Fused_RoPE_NPU.ipynb)

## 一句话总结

这个 notebook 教你用 Triton 写融合的旋转位置编码（RoPE）：每个 Program 负责一个位置的一个注意力头，把相邻两个特征分量当作平面上的一个点做二维旋转，再原位写回。

## 为什么需要它：痛点是什么

RoPE 是大模型里给 Query/Key 注入位置信息的标准操作。它本身不复杂——每对分量转一个角度——但朴素 PyTorch 实现要生成多份中间张量（旋转矩阵、乘积、拼接），显存来回跑；而且"在原地改数据"这件事藏着陷阱：一对特征 $(a,b)$ 的两个输出都依赖原始的 $a$ 和 $b$，如果你先把新 $a'$ 写回原地址，再用这个位置的数据算 $b'$，算出来的就已经不是同一个旋转了。这就像调换一杯水和一杯果汁需要第三个空杯——没有空杯（临时变量），先倒的那杯就毁了。

## 核心问题

- 为什么两个相邻分量必须一起旋转、一起写回？
- 一个 Program 怎样从自己的编号找到"哪个位置、哪个头"的特征和角度？
- 原位写回要遵守什么契约？

## 解决思路：一步步看懂

1. **成对旋转。** 输入 $X$ 形状为 $(S,H,D)$（序列位置数、注意力头数、每头特征维度，D 为偶数）。取第 $i$ 对特征 $a=X_{p,h,2i}$、$b=X_{p,h,2i+1}$，按角度 $\theta_{p,i}$ 旋转：

   $$a'=a\cos\theta-b\sin\theta,\qquad b'=a\sin\theta+b\cos\theta$$

   文字说：两个输出用的是**同一对原值**交叉乘加。例：$(a,b)=(1,2)$、角度 $\pi/2$ 时 $(\cos,\sin)=(0,1)$，得 $(-2,1)$。

2. **编号解码：除头数得位置。** 共 $S\times H$ 个 Program，编号 $t$ 对应位置 $p=\lfloor t/H\rfloor$、头 $h=t\bmod H$。关键在角度表形状是 $(S,D/2)$——**不含头维度**：

   ```python
   token_idx = pid // n_heads              # 位置 = 编号整除头数
   freq_offset = token_idx * half_dim + pairs  # 角度表行偏移，头编号不进入
   ```

   例：H=2、D=6 时，Program 2 和 3 同属位置 1，特征起点分别是 12 和 18，但读的角度表行都从偏移 3 开始。同一角度用于多个头叫广播（broadcast）——共用角度，不共用特征。

3. **两路原值、两路输出。** 参考实现先载入偶数分量 `x_evens` 和奇数分量 `x_odds`（升 FP32 计算），然后：

   ```python
   out_evens = x_evens * cos_vals - x_odds * sin_vals  # 用原来的两路值
   out_odds  = x_evens * sin_vals + x_odds * cos_vals  # 不是已写回的新值
   ```

4. **原位写回。** 原位（in-place）指结果写回输入的同一存储位置。两路都算完后再 `tl.store` 两次（偶数、奇数各一次），共用掩码 `pairs < half_dim`。每对特征只有唯一 Program 处理，所以不会互相踩踏；启动器要求 X 连续、角度表不得与 X 共享存储，最后返回的就是 X 本身（地址不变才算原位）。

5. **尾部掩码。** `BLOCK_SIZE = next_power_of_2(head_dim)`，非 2 次幂维度（如 6、48、96）补齐的位置只参与计算、没有写回权限。

## 关键概念速查表

| 术语 | 大白话解释 |
|---|---|
| RoPE | 旋转位置编码，把每对分量按位置角度旋转以注入位置信息 |
| 头（head） | 一份独立的特征向量，同一位置各头共用旋转角度 |
| 特征对 | 相邻的 $(x_{2i}, x_{2i+1})$，被当作平面上的一个点 |
| 广播（broadcast） | 同一角度表行发给同位置的多个头使用 |
| 原位（in-place） | 结果写回输入原地址，返回张量与输入同存储 |
| 掩码（mask） | 补齐位置不读不写，只有 $i < D/2$ 的对有效 |
| `pid // n_heads` | 从扁平 Program 编号恢复位置索引 |
| FP32 中间计算 | 乘加用 32 位浮点算完，再按输入类型舍入 |

## 小白常见疑问

- **Q：先写回偶数分量再算奇数分量，数值差多少？** 不是精度问题，是算错了：奇数分量用到的是被覆盖后的假 $a$，结果不再是同一个旋转。先算完两路、再一起写回。
- **Q：角度表偏移能用 `pid * half_dim` 吗？** 不能。角度表没有头维度，必须先 `pid // n_heads` 得到位置；用 pid 会把"头的编号"错当"位置"。
- **Q：为什么角度表不能和 X 共享存储？** 写回特征若覆盖了其他 Program 还要读的角度，头之间就产生读写依赖，破坏原本独立的旋转；启动器会保守拒绝。
- **Q：怎么自检旋转做对了？** 用零角度（应恒等）、四分之一圈（方向交换带符号）这类真实角度检查，另核对每对特征的长度是否保持不变。

## 动手验证：怎么知道自己做对了

`_check_rope_case` 用 PyTorch 参考实现 `reference_rope` 逐元素对照（FP32 中间计算约定一致），并检查：零角度得到原值、四分之一圈得到 $(\mp b, a)$ 式的方向交换、每对特征长度保持、返回张量地址与 X 相同（原位契约）、频率表未被修改。用例覆盖非 2 次幂维度（6/48/96）、多头多位置、非连续角度表；`test_rope_input_contract` 验证非法输入（维度 7 或 258、形状不符、共享存储等）被拒绝。性能测量对比"PyTorch 参考分配新输出"与"Triton 先 clone 再原位旋转"两条完整调用路径（候选时间含 clone），五轮交替顺序、先核对数值再计时。
