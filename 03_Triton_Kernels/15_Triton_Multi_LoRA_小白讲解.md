# 15. Triton 多 LoRA 融合推理（Token 路由 + 低秩增量） — 小白讲解

> 对应 notebook：[`15_Triton_Multi_LoRA.ipynb`](./15_Triton_Multi_LoRA.ipynb)

## 一句话总结

这个 notebook 教你写一个 kernel，让同一批输入里**每一行 token 按自己的编号**去共享的适配器权重池里取一套 LoRA 矩阵，完成两次低秩乘法，得到各自的增量输出。

## 为什么需要它：痛点是什么

LoRA（Low-Rank Adaptation，低秩适配）是微调大模型的省钱办法：不动原模型权重 $W$，只在旁边加一对小矩阵——先乘 $A$（$D_{in}\to R$，R 是很小的秩）把维度压低，再乘 $B$（$R\to D_{out}$）投影回去，输出增量 $\Delta Y = XA^{\mathsf T}B^{\mathsf T}$。训练只需存这对小矩阵。

推理服务真正赚钱的玩法是 **Multi-LoRA**：一个底座模型同时服务成百上千个用户，每个用户有自己的 LoRA 适配器（聊天风格、领域知识各不相同）。如果用朴素 PyTorch 实现：每个请求单独跑一遍 `x @ A @ B`，就要为每种适配器反复提交小 kernel、反复切换；或者干脆把整批输入路由到同一个适配器——那其他用户的"个性化"就全没了。

生活类比：快递分拣中心（GPU）。包裹（token）堆在同一条传送带（一个批次）上，每个包裹的面单（路由编号 $r_i$）写着要去哪个货架（适配器）。高效的做法是包裹经过时，分拣员现场看面单、从对应货架取出工具（A、B）就地加工，而不是每张面单开一条专用传送带，更不是无视面单统一发到一个货架。

本节把所有适配器堆成一个只读权重池，让"取哪套权重"变成 kernel 内部的一次查表。

## 核心问题

1. 每行 token 怎样用同一个编号 $r_i$ 分别定位 A、B 两个形状不同的池？
2. 两次低秩归约（先沿输入维算 h，再沿秩维算输出）怎样在一个 program 里完成？
3. 路由/权重重排时，哪些对应关系必须保持，输出才不变？

## 解决思路：一步步看懂

**第 1 步：数据长什么样。** 输入 $X\in\mathbb R^{M\times D_{in}}$，路由向量 $r\in\mathbb Z^M$；A 池形状 $(L,R,D_{in})$，B 池 $(L,D_{out},R)$（L 是适配器数，R 是低秩维度）。第 $i$ 行的计算：

$$h_i=X_iA_{r_i}^{\mathsf T}\quad(\text{压到 } R \text{ 维}),\qquad \Delta Y_i=h_iB_{r_i}^{\mathsf T}$$

两次乘法**必须选同一个 $r_i$**。路由是 [2,0,1,2] 时，第 0、3 行都读 A₂、B₂，但各自用自己的输入算 h，输出互不相干。注意输出只是增量 $\Delta Y$，不含基础投影 $XW^{\mathsf T}$；LoRA 常见的 $\alpha/R$ 缩放已预先合入 B，kernel 里不能再乘一次。

**第 2 步：一个 program 的完整工作。** 二维 grid 第一维选 token 行，第二维选输出列块（`BLOCK_IN=64, BLOCK_OUT=32`）。程序先查路由、定位两个池的基址——A、B 形状不同，**池步长不同，不能共用一个偏移**：

```python
# TODO 1：两组基址使用相同路由编号、不同池步长。
lora_idx = tl.load(lora_indices_ptr + pid_m)  # 读当前 token 的适配器编号
a_base = lora_idx * stride_a_lora             # A 池：编号 × A 的池步长
b_base = lora_idx * stride_b_lora             # B 池：同一个编号 × B 的池步长
```

然后沿输入宽度分块累加 $h$（$D_{in}=70$ 走两轮，第二轮只补最后 6 项，`h_r` 必须累加而不是覆盖），再把 $h$ 与当前输出块的 B 沿 R 维归约（`tl.sum(h_r[None, :] * b_val, axis=1)`，只消秩轴、保留输出列）。

**第 3 步：秩补齐也要屏蔽。** R=3 在计算里补到 4（Triton 块大小须是 2 的幂），第 4 项不属于模型，A、B 两处加载都要用 `offs_r < R` 排除，否则补齐位置会混进归约。输出写回按真实输出宽度屏蔽尾部列（$D_{out}=65$ 分三块，最后一块只写第 64 列）。

**第 4 步：什么变了输出必须不变。** 把输入行和路由**一起**置换，输出应随之置换；同时重排 A/B 池的适配器顺序并按逆映射更新路由，每行读到的实际矩阵不变，增量也不变。但只重排 A、B 中的一个池会破坏配对——这是检查"两次乘法用了同一路由"的试金石。

## 关键概念速查表

| 术语 | 大白话解释 |
|---|---|
| LoRA | 不动原权重、旁挂一对低秩小矩阵的微调方案 |
| 低秩（low-rank）/ R | 中间瓶颈维度，远小于输入输出宽度 |
| 适配器（adapter） | 一对 A、B 矩阵，本节指低秩增量，不是另一份完整模型 |
| 权重池（pool） | 把 L 套适配器堆叠成的一个只读三维张量 |
| 路由（routing）/ lora_indices | 长度为 M 的整数向量，给每行 token 指定适配器编号 |
| 池步长（pool stride） | 池内"跨一个适配器"要跳过的元素数，A、B 各不相同 |
| h（中间向量） | 输入压到 R 维的低秩表示，第一段乘法的产物 |
| 秩补齐 | R 不是 2 的幂时补到最近的 2 的幂，补出位置要屏蔽 |
| 基础投影 / 缩放合入 B | 输出不含 XW^T；alpha/R 已折进 B，kernel 不再乘 |

## 小白常见疑问

**Q1：为什么不能按批次选一套权重统一算？**
路由是**逐行**的：[2,0,1,2] 里四行用三套不同适配器。只按第一行选权重，其余行的个性化更新就全被忽略了。共享的是权重（第 0、3 行共用 A₂B₂），不是输入或输出。

**Q2：A 和 B 能用同一个偏移公式寻址吗？**
不能。A 池是 $(L,R,D_{in})$、B 池是 $(L,D_{out},R)$，形状不同、步长不同，必须各自用"编号 × 池步长"定位基址，再叠加各自内部的行列表偏移。

**Q3：这个 kernel 融合了两段乘法，还有浪费吗？**
有。当前按输出块分别启动，同一个 token 的 h 会在不同输出块里重复计算（65 列、块宽 32 时第一段乘法执行三遍）。先算好存下 h 的两阶段方案只算一遍，但多了 h 的写回读取和一次 kernel 提交，孰优孰劣要按完整调用统计，不能只看"是否融合"。

**Q4：输出怎么比对才公平？**
参照实现 `reference_multi_lora` 用双精度逐行算 $(x_i A^T B^T)$ 再转回 FP32，避开单行 FP32 累加的误差干扰。

## 动手验证：怎么知道自己做对了

`_check_lora` 与双精度逐行参照对比（atol=1e-3），并核对输出形状、dtype、设备、连续性、有限性和输入不变性。测试覆盖非整块特征（$D_{in}=70$）、非二次幂秩、混合路由 [2,0,1,2]、零 A/零 B（对应行增量必须为 0）、带步长视图，以及第 4 步那组置换/重排不变量。`test_lora_input_contract` 验证负数或越界路由、形状不匹配、autograd 输入在启动前被拒绝。
