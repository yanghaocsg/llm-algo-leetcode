# 18. Triton 编译产物与实际执行核对 — 小白讲解

> 对应 notebook：[`18_Triton_Compilation_Artifacts_and_Execution.ipynb`](./18_Triton_Compilation_Artifacts_and_Execution.ipynb)

## 一句话总结
回答两个工程问题：同一段源码换个 BLOCK 还是同一份生成代码吗（编译特化身份）？以及"代码准备好了"和"GPU 真的执行了"怎么区分——用一个缩放加偏置 kernel 把源码、编译产物、实际调用三层串起来核对。

## 为什么需要它：痛点是什么
调 Triton 时常见的糊涂账：日志里的 kernel 名字没变，就以为跑的是同一份代码；调用完输出对了，就以为刚才准备的那份产物被执行了。实际上多份特化产物可以共用同一个入口名，准备阶段也可能只是命中缓存、根本没碰 GPU。就像你打电话订了出租车（编译准备），不代表车已经开到你楼下（GPU 执行）；而楼下停过的车也不一定就是你订的那辆（同名不同产物）。这节教的核对手段，解决的正是"我调的到底是不是我想的那份代码"这个实际问题。

## 核心问题
- 哪些条件（常量、类型、设备）决定一份编译产物？改变 BLOCK 会不会得到新代码？
- 长度、缩放系数这些运行时参数变化时，为什么可以复用已有产物？
- 怎么证明"这份产物"在"这次调用"里真的被 GPU 执行了？

## 解决思路：一步步看懂
1. **源码 ≠ 产物**。源码只定义计算；生成的实现还取决于输入类型、编译期常量、编译选项和目标 GPU。BLOCK=128 和 BLOCK=256 改变一个 program 的工作范围，即使输出相同，也是两份不同产物——函数名不是唯一身份。
2. **编译期常量 vs 运行时参数**。本页 kernel 用 `@triton.jit(do_not_specialize=["n_elements", "alpha", "bias"])` 声明长度和系数不按数值特化：
```python
full_block = n_elements % block == 0   # 长度能被块宽整除，才能省去掩码
y = alpha * x + bias                   # 系数是运行时输入，不能写死
```
于是长度 512 和 768 都能复用 BLOCK=128 的"完整块无掩码"产物；alpha 从 0.5 改成 -1.5 不触发重编译，但新值必须真的作用到输出。而 `FULL_BLOCK`、`BLOCK` 是 `tl.constexpr`，改变它们就改变编译身份。
3. **看得到产物**。编译 lowering 链条是 TTIR→TTGIR→LLVM IR→PTX→cubin（SASS 对应机器指令）。骨架提供 `artifact_payloads`（读取 `compiled.asm` 里的文本 IR、PTX 和二进制）、`compilation_manifest` 和导出函数；导出后重新计算 SHA256 核对内容。测试里还会对照"相同条件复用同一份产物"与"BLOCK 改变后身份不同"。
4. **区分准备和执行**。`inspected_affine_kernel.warmup(...)` 只准备产物不执行。真执行要直接启动这个已编译对象（TODO 3 的 `compiled[grid](...)`），按 kernel 签名传指针、长度、系数和两个编译期常量，不许改走 PyTorch 或重新走 JIT 选择。
5. **联合证据链**。输出先填 NaN（准备阶段不许写它）；`LaunchObserver` 记录被调用的对象、网格与参数；torch.profiler 的 CUDA 事件记录 GPU 活动；最后核对输出数值。测试还专门准备了一个"绕过编译对象、用别的路径算出正确数值"的 `substituted_launch` 替身——它必须被拒绝，说明测的是路径本身而不是"结果对就行"。

## 关键概念速查表
| 术语 | 大白话解释 |
|---|---|
| 特化（specialization）| 按常量/类型/设备生成的一份具体代码 |
| tl.constexpr | 编译期常量，写死进生成代码，改它就换产物 |
| do_not_specialize | 声明某参数按运行时值处理，不参与数值特化 |
| FULL_BLOCK | 编译期布尔：网格是否全由完整块组成，成立可省掩码 |
| warmup | 只准备/获取编译对象，不启动 GPU 执行 |
| TTIR / TTGIR / PTX / cubin | 从高层 Triton IR 到 GPU 二进制的逐级产物 |
| guard（适用条件）| 一份产物能被复用前要满足的输入条件 |
| torch.profiler | 采集 CUDA 活动事件，证明 GPU 真的执行了 |

## 小白常见疑问
- **Q：为什么不能靠 kernel 名字区分产物？** 多份特化产物共用入口名；身份由源码、编译期常量、目标与编译选项共同决定，所以要配合摘要（hash）和调用记录一起看。
- **Q：alpha 变了为什么不重编译？** 它被声明为不按数值特化的运行时参数；同设备、相同输入签名下复用同一份二进制，新值在运行时生效。
- **Q：warmup 之后输出为什么还是 NaN？** warmup 只准备代码不执行；测试用这一点确认"准备阶段没有偷偷写输出"，真正写输出要等直接启动编译对象。
