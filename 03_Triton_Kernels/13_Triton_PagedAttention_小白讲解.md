## 一句话总结

这个 notebook 教你把 KV cache 从"每个请求一段连续大内存"改成"按页分散存放 + 查页表访问"，解决显存碎片和浪费，同时注意力结果和连续存放时一模一样。

## 为什么需要它：痛点是什么

先说 KV cache（键值缓存）为什么存在：解码每生成一个 token，都要用新查询对**全部历史** K/V 做注意力。历史 K/V 算一次就可以反复用，所以推理服务会把它们缓存在显存里。

朴素方案是给每个请求预分配一段连续显存，按"最大可能长度"预留。这有两个大问题：

1. **内部浪费**：请求实际只聊了 3 句话，却占着按 4096 token 预留的位置，空着的位置谁也用不了。
2. **外部碎片**：请求长短不一、来去不停，反复分配释放大段连续显存，最后整块显存没剩多少，却到处是不连续的小洞——新请求放不进来。

生活类比：停车场只卖"固定长条车位"， 短车（短请求）也占一整条，车走了还留下不规整的空位。PagedAttention 的解法和操作系统内存分页一个思路：把停车场划成一格一格的标准车位（页，page），每辆车按需占几格，格子和格子不必相邻；每辆车有一张"停车位置单"（页表，page table）记录自己的第几段在哪个格子。逻辑上连续的上下文，物理上散落各处。

代价是取数时多一步"查表"：这就是间接寻址（indirect addressing）——先读表项拿到物理页号，再用页号算真正的数据地址。

## 核心问题

1. 逻辑位置 $t$ 怎样经过页表找到物理页和页内槽位？
2. 有效长度 $L$ 怎样决定遍历几张页、尾页哪些槽位无效？
3. 物理页摆放变化（甚至被多个请求共享）时，为什么注意力结果不变？

## 解决思路：一步步看懂

**第 1 步：两级定位。** 查询 Q 形状 $(B,H,D)$（解码每请求 1 个新查询），缓存池形状 $(P,C,H,D)$：$P$ 个物理页、每页 $C$ 个 token 槽位，一个槽位存该位置**所有头**的键值。页表 $T$ 一行属于一个请求，**列号是逻辑块，表项才是物理页号**。对逻辑位置 $t$：

$$\ell=\lfloor t/C\rfloor,\quad r=t\bmod C,\quad p=T_{b,\ell},\quad \text{读 } K_{p,r,h,:}$$

notebook 的例子务必亲手推一遍：$C=4$、页表 $[5,1,7]$，位置 6 拆成逻辑块 1、页内偏移 2，于是读**物理页 1 的槽位 2**——不是物理页 6，也不是页 1 的槽位 6。

**第 2 步：按有效长度决定查几张页。** $L$ 个有效位置需要 $\lceil L/C\rceil$ 个表项。$C=4,L=6$ 时页表 $[5,1,7]$ 只用前两项：页 5 的四个槽位全有效，页 1 只有槽位 0、1 有效，页 7 根本不读。尾页的判断必须用全局逻辑位置 $t=\ell C+r<L$，而不是 $r<C$（后者恒成立，会把尾页空槽全算进去）。未用的表项放 -1 哨兵无所谓，反正不读；启动前主机侧会核对有效表项都指向真实物理页。

**第 3 步：跨页合并同一份 Softmax 状态。** 关键认识：**页只是读取单位，不是归一化范围**。每页各自做 Softmax 再平均，会给长短页、分数不同的页分配错误权重。正确做法沿用第 11 篇的在线状态：保留历史最大值 $m$、指数和 $l$、加权和 $a$，读入新页后取新基准 $m'=\max(m,\max s)$，用 $\alpha=e^{m-m'}$ **同时**修正旧 $l$ 和旧 $a$，累加本页贡献；所有页处理完才输出 $a/l$。例子：旧页最大分数 0、新页 $\ln 2$，旧分母和加权和都要乘 $1/2$——漏掉任何一个修正都会改变历史与新位置的相对权重。

**第 4 步：共享与不变性。** 页可以只读共享：请求 A 和 B 都在自己的页表里写上页 5，就共享了同一段 K/V（比如多条对话共用同一段系统提示词）。但每个请求仍用自己的查询和 Softmax 状态，共享不等于合并。只重新摆放物理页并同步更新页表，逻辑数据不变，输出也应不变——这正是测试要验证的。

## 关键概念速查表

| 术语 | 大白话解释 |
|---|---|
| KV cache | 缓存下来的历史 Key/Value，解码时反复被新查询读取 |
| 物理页（page）/ 槽位 | 缓存池 (P,C,H,D) 里的一页及其内含的 C 个 token 位置 |
| 页表（block table） | 每请求一行的映射表：列号=逻辑块，表项=物理页号 |
| 间接寻址 | 先读表项拿页号，再用页号算数据地址，多一次查表 |
| 逻辑块 / 页内偏移 | 位置 t 拆成 t//C 和 t%C 两级坐标 |
| 哨兵值 -1 | 页表未使用列的占位符，内核不读它 |
| 只读共享页 | 多个请求页表指向同一物理页，省显存且互不干扰 |
| 在线 Softmax 状态 | 跨页归一化的最大值 m、指数和 l、加权和 a 三件套 |
| 外部/内部碎片 | 大段分配留下的不连续空位／预留过长造成的段内浪费 |

## 小白常见疑问

**Q1：为什么不干脆给每个请求分配最大长度的连续缓存？**
显存会被大量"占着不用"的位置和碎片耗尽，能同时服务的请求数大幅减少。分页把浪费压缩到每个请求最多不到一页。

**Q2：每页先做 Softmax 再拼起来行不行？**
不行。Softmax 的分母必须覆盖全部有效位置；每页单独归一化再平均，等于假设各页权重相等，会系统性偏差。必须用 $\alpha$ 修正把所有页的贡献换到同一基准。

**Q3：查页表会不会拖慢速度？**
有一点成本：表项要先从显存读出来。另外启动器核对页表合法性需要设备到主机的等待，`benchmark_paged_attention` 特意把这部分也计入计时——真实工程里这是要权衡的开销。

**Q4：这个 kernel 负责页的分配和释放吗？**
不负责。缓存只读，分配、回收、引用管理、写时复制属于调度器的职责，本节只做"查表 + 计算注意力"这一件事。
