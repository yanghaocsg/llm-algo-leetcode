## 一句话总结

通过手写矩阵转置，搞懂二维张量的地址不是按"几行几列"算的，而是按步长（stride）算的——形状变了数据未必搬家，步长才是通往真实存储位置的地图。

## 为什么需要它：痛点是什么

在 PyTorch 里 `x.t()` 一行就"转置"了，但它通常只是交换了形状和步长、共享原来的存储——像把书架的标签换了，书还没挪。如果后面的运算需要一份真正连续的转置结果，就必须真的把每个元素读出来、写到新位置。

用朴素 PyTorch 时你不需要关心这件事（`x.t().contiguous()` 帮你搬），但自己写内核时就要回答：输入位置 (i, j) 应该读哪个地址？又该写到输出的哪个位置？最容易踩的坑是：拿"逻辑行宽"当步长用。比如连续 2×3 矩阵的转置视图形状是 3×2、步长是 (1, 3)，位置 (0, 1) 的偏移是 3，不是想当然的 1。就像小区门牌号不能按"第几栋第几单元"猜，得看实际的楼间距。

## 核心问题

- 转置视图的逻辑坐标 (i, j) 怎么通过真实步长换算成存储偏移？
- 一个 Program 怎么用矩形 tile（数据子块）处理二维数据，行列两个方向怎么同时加掩码？
- 写回时为什么数据、坐标、mask 三者要一起"转置"？

## 解决思路：一步步看懂

1. **坐标换地址**：输入位置 (i, j) 相对视图首元素的偏移是 `i*stride_x0 + j*stride_x1`，其中 s0、s1 是以元素为单位的实际步长（stride，某一维索引加 1 时存储前进的元素数）。注意传入的指针已经指向视图首元素，不能再重复加存储偏移。带步长切片还会同时改变起点与间隔：5×7 连续矩阵取行 1、3 和列 2、4、6，得到步长 (14, 2) 的视图。
2. **二维 tile 定位**：kernel 用二维 grid，`rows = tl.program_id(0)*BLOCK_M + tl.arange(0, BLOCK_M)`，`cols` 同理（本题 `block_m, block_n = 16, 32`）。行坐标是 16×1 列向量、列坐标是 1×32 行向量，广播相加得到 16×32 的地址矩阵。
3. **两维 mask**：行号 < M **且** 列号 < N 才有效，两个条件缺一不可。19×35 的输入右下角 tile 只有 3×3 个有效元素，其余补零并屏蔽。
4. **读、转、写**：

```python
x_offsets = rows[:, None] * stride_x0 + cols[None, :] * stride_x1  # 真实步长寻址
mask = (rows[:, None] < M) & (cols[None, :] < N)                   # 行列同时有效
tile = tl.load(x_ptr + x_offsets, mask=mask, other=0.0)            # 读入 16×32 子块
y_offsets = cols[:, None] * M + rows[None, :]                      # 输出坐标交换
tl.store(y_ptr + y_offsets, tl.trans(tile), mask=tl.trans(mask))   # 数据、mask 一起转置
```

关键在最后一行：`tl.trans` 把 tile 和 mask 一起交换维度，变成 32×16 的输出块。若只转置数据不转置 mask，数据位置就和写入权限错配——补进来的零可能被当成合法输出写出去。输出用连续布局，Y 的偏移统一是 `j*M + i`。

## 关键概念速查表

| 术语 | 大白话解释 |
|---|---|
| stride（步长） | 某一维索引加 1 时，在存储中前进的元素数 |
| 视图（view） | 只改形状/步长、共享原存储的张量，如 `x.t()` |
| tile（子块） | 一个 Program 负责的矩形数据块，如 16×32 |
| 二维 grid | 用两个维度的 Program 编号覆盖行、列两个方向 |
| 广播（broadcast） | 16×1 与 1×32 的坐标相加自动展开成 16×32 矩阵 |
| `tl.trans` | 交换一个二维块的两个维度 |
| `x.stride()` | PyTorch 返回张量各维真实步长，启动时传给 kernel |
| 连续（contiguous） | 元素在内存中按索引顺序紧邻存放 |

## 小白常见疑问

**Q1：`x.t()` 不是已经转置了吗，为什么还要写内核？**
`.t()` 只是转置视图：形状换了、数据没动，步长变成 (1, 3) 这种"跳跃"访问。需要独立、连续的转置结果时，必须实际搬运数据——这正是本节 kernel 做的事。

**Q2：能不能用逻辑行宽（比如 N）代替 stride？**
只有连续输入时碰巧一致。转置视图、带步长切片、广播展开的输入步长各不相同，拿逻辑形状当步长会读错地址——而且形状还是"对"的，数值却全错了，非常隐蔽。

**Q3：为什么 mask 也要转置？**
mask 标记的是"哪些位置有效"。数据转置后，第 (j, i) 个输出对应原来的 (i, j)，有效位置也跟着换了位置。不转 mask 就会出现"把补零位置写出去、真位置反而不写"的错配。

**Q4：输出的偏移为什么是 `cols*M + rows`？**
输出 Y 是 N×M 连续矩阵，位置 (j, i) 的偏移是 j*M+i；而 j 来自输入列 cols、i 来自输入行 rows，所以两个坐标直接换位相乘相加。
