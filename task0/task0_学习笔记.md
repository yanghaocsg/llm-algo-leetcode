## 一、推理模型架构组成

以仅解码器 Transformer 为例，模型 = **数字表示 → 上下文加工 → 下一个 token 预测**：

| 组件 | 作用 |
|------|------|
| **Embedding** | token ID → 向量 |
| **多层 Transformer Block** | 因果自注意力（结合上下文）+ 前馈网络（变换表示）+ 归一化 + 残差；位置信息区分 token 顺序 |
| **最终归一化 + LM Head** | 隐藏表示 → 词表上各 token 分数 → 采样/解码选下一个 token |
| **Tokenizer** | 文本 ↔ token ID（token 可能是字、词或子词，不等于固定汉字数） |

## 二、请求生命周期与核心指标

### 请求流程

```
请求到达 → 排队与准入 → 输入准备 → Prefill → 首个输出 token → Decode → 完成/取消/超时/失败
```

### Prefill vs Decode

| 阶段 | 动作 | 直觉 |
|------|------|------|
| **Prefill** | 处理已有输入，建立 KV Cache，得到首个输出 token | 先处理问题和已有上下文 |
| **Decode** | 读取历史 KV + 最新 token，预测后续 token，追加状态 | 沿着已写内容继续写 |

> **KV Cache**：保存历史注意力 Key/Value，Prefill 建立、Decode 读取追加，避免重复计算。不是独立串行阶段，也不意味着后续生成无需计算。

### TTFT vs TPOT

| 指标 | 定义 | 回答的问题 | 本练习计算 |
|------|------|-----------|-----------|
| **TTFT** | 请求到达 → 首 token 时间 | 开始回答前等多久？ | 排队 + 输入准备 + Prefill |
| **TPOT** | 相邻输出 token 间隔均值 | 开始后平均多久出一个 token？ | 间隔数 = token数 - 1，不足 2 个 token 为 None |

### 教程样例（单位：ms）

| 事件 | 到达 | 准入 | 输入就绪 | 首 token | token2 | token3 | 完成 |
|------|------|------|----------|----------|--------|--------|------|
| 时间 | 0 | 2 | 3 | 7 | 9 | 11 | 12 |

- **TTFT** = 7 - 0 = 7 ms = 排队(2) + 准备(1) + Prefill(4)
- **TPOT** = [(9-7) + (11-9)] / 2 = 2 ms/token（3 个 token 只有 2 个间隔）
- **端到端** = 12 ms（最后 token 到完成的 1ms 不计入 TPOT）
- 无首 token 时 TTFT = None；不足 2 个输出 token 时 TPOT = None，**不能用零填充**

## 三、工作负载与统计口径

- 比较性能必须固定：输入/输出长度、并发、到达模式、缓存策略、执行后端
- 取消和失败也要记录，**成功率与平均 TTFT 的统计样本可能不同**
  - 成功率分母 = 全部终止请求（含失败）
  - TTFT 均值分母 = 有有效 TTFT 的请求（首 token 前取消的不计入）
