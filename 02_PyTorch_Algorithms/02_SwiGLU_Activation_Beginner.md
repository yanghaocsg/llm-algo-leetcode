## 一句话说清

SwiGLU 是大模型里一段小网络的写法：把每个词元的向量分成两路，一路当闸门去乘另一路，让每个特征有自己的通过强度。这本 notebook 教你算它的宽度，并动手写出这段计算。

## 为什么需要它

Transformer 的 MLP（也叫前馈网络）做三件事：把向量升维、过激活函数、再降维。想把它换成 SwiGLU，会遇到三个问题。

- **一条路，没法单独取舍**。普通写法里，所有中间特征一起过同一个激活函数。闸门为 `2.0` 的特征和闸门为 `0.0` 的特征，本该一个放大、一个挡住，单路激活没有地方表达这种差别。
- **多了一条路，参数变多**。SwiGLU 比普通写法多一个投影。隐藏维 `d = 12` 时，普通写法的中间维取 `48`，参数量是 `1152`；SwiGLU 如果也取 `48`，参数量就是 `1728`。中间维必须重新算。
- **把闸门读成概率**。闸门值看着像 0 到 1 之间的“通过率”，其实可以为负，也可以大于 1。按概率去理解，后面的形状和数值都会想错。

这本 notebook 做两件事：推出 SwiGLU 的中间维该取多宽，再把“两路相乘、投回隐藏维”写成代码。

## 先认识几个词

| 词 | 人话解释 |
|:---|:---|
| 前馈网络（FFN） | 也叫 MLP：把向量升维、过激活函数、再降维的那一段网络 |
| 隐藏维 `d` / 中间维 `h` | `d` 是输入向量的长度（`hidden_size`）；`h` 是变长之后的长度（`intermediate_size`） |
| 投影（projection） | 一个线性层 `nn.Linear`，用矩阵把向量从一种长度变成另一种长度。本节有 gate、up、down 三个 |
| 激活函数 / SiLU | 逐元素的小函数，给网络加入非线性。SiLU 的定义是 `x * sigmoid(x)`，输出可以为负，也可以大于 1 |
| 逐元素（element-wise） | 两个形状相同的张量在相同位置上两两运算，比如 `SiLU(gate) * up` |
| 门控（gating） | 用一条分支的数值当闸门，逐元素乘到另一条分支上，控制每个特征通过多少 |
| 参数量 / 容量 | 参数的个数。notebook 用“容量”比较两种结构：参数预算相近时，中间维各该取多宽 |

## 核心思路

SwiGLU 的输入是形状 `[B, S, d]` 的张量，每个词元是一个长度为 `d` 的向量。它做四步，输出形状和输入一样：

```text
gate_up = gate_up 投影(x)             # [B, S, 2h]：一次算出两条分支
gate, up = 沿最后一维切成前后两半      # 各是 [B, S, h]
gated   = SiLU(gate) * up             # 逐元素相乘
y       = down 投影(gated)            # [B, S, d]：投回隐藏维
```

符号说明：`d` 是隐藏维，`h` 是中间维；`up` 是候选分支，提供候选特征；`gate` 是门控分支，决定每个候选特征通过多少。三个投影都是不带偏置的 `nn.Linear`。其中 gate 和 up 两个投影拼成一个“融合投影”，一次输出 `2h` 个数，再切开。

中间维取多宽？标准 FFN 有 up、down 两个投影，每个投影的权重是 `d × h` 的矩阵，参数量约 `2dh`；取 `h = 4d` 时约 `8d²`。SwiGLU 有 gate、up、down 三个投影，参数量约 `3dh`。要在相近的参数预算下比较，就让 `3dh` 约等于 `8d²`，解出 `h ≈ 8d/3`。它通常不是整数，再向上对齐：取不小于它的、最小的 `multiple_of` 的倍数。

下面用小数验证门控和这两笔账：

```python
import torch
import torch.nn.functional as F

gate = torch.tensor([2.0, -1.0, 0.0])   # 门控分支
up = torch.tensor([3.0, 3.0, 3.0])       # 候选分支
print(F.silu(gate))                      # 门控值：可以为负，也可以大于 1
print(F.silu(gate) * up)
print(torch.sigmoid(gate))               # 换成 Sigmoid 门，就都落在 0 到 1 之间

d = 12
print(2 * d * 4 * d, 3 * d * int(d * 8 / 3))    # 标准 FFN 与 SwiGLU 的参数量
print(int(4096 * 8 / 3), ((int(4096 * 8 / 3) + 255) // 256) * 256)
```

```text
tensor([ 1.7616, -0.2689,  0.0000])
tensor([ 5.2848, -0.8068,  0.0000])
tensor([0.8808, 0.2689, 0.5000])
1152 1152
10922 11008
```

门控值 `2.0` 变成 `1.7616`，`-1.0` 变成 `-0.2689`，`0.0` 还是 `0`；三个候选特征都是 `3.0`，乘完后各不相同。换成 Sigmoid，三个门控值都落在 0 到 1 之间。最后两行是两笔账：`d = 12` 时两种结构的参数量都是 `1152`；隐藏维 `4096` 的理论中间维是 `10922`，向上对齐到 `11008`，这正是 notebook 测试里要求的配置。

## 容易踩的坑

- **把门控值当概率或开关**：SiLU 的输出可以为负，也不受 1 限制，不能解释成概率或二值掩码。
- **两条分支没有逐元素对应**：门控分支和候选分支的特征宽度要一致，位置要一一对应，不是两组可以任意配对的特征。
- **对齐时四舍五入或向下取整**：对齐后的中间维必须不小于理论维度，并且能被 `multiple_of` 整除，所以要向上取整。
- **融合投影的宽度或偏置不对**：`gate_up_proj` 的输出要是 `2 × intermediate_size`，`down_proj` 要投回 `hidden_size`，两个都不带偏置。
- **输出没有回到隐藏维**：MLP 的输出形状必须和输入一样。残差相加与归一化属于模型块的外层关系，不写进这个 MLP。
