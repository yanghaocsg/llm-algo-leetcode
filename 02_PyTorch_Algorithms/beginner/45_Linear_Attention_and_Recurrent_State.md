## 一句话说清

标准注意力要保留历史上每个词元的键和值。线性注意力改成只保留一份固定大小的累计状态，每来一个词元就更新它，再从状态里读出当前的输出。

## 为什么需要它

标准注意力在每一步，都要拿当前的查询去和全部历史键逐个比较。历史有多长，要保存的访问关系就有多少。

这本 notebook 的 GPU 实验给了一组对照：完整历史的显式状态在 512 个词元时是 1 MiB，到 8192 个词元时涨到 16 MiB；固定大小的递推状态一直是 0.0625 MiB。这组数字只验证单层的状态接口，不代表真实模型的质量。

线性注意力换了一种保存历史的形式：不保留一个个词元对，而是把历史的键和值汇总成一份固定形状的状态。新词元到来时更新状态，再生成输出。代价是读出来的只有汇总后的统计量，不能像 KV Cache 那样按词元取出某一条历史。而且特征映射改变了相似度的形式，所以它是一类注意力近似，不是免费替代。

这本 notebook 用一个简化的正特征映射，把“更新状态”和“读取输出”写成几行代码，再检查两件事：状态的形状是否固定，未来的词元会不会改变之前的输出。它只验证递推机制，不把结果写成真实模型的吞吐结论。

## 先认识几个词

| 词 | 人话解释 |
|:---|:---|
| 词元（token） | 模型处理文本的最小单位，这里一个词元占一个时间步 |
| 查询 / 键 / 值（Query、Key、Value，Q/K/V） | 注意力的三路输入。查询去和每个键比较，再按比较结果把对应的值加权求和 |
| 特征映射（feature map）`φ` | 对查询和键各做一次变换的函数。本节用 `relu(x) + 1`，保证结果全是正数 |
| 递推状态（recurrent state） | 汇总历史的一份数字，形状固定。本节有两份：`S_t` 汇总键和值，`z_t` 汇总键 |
| 归一化项 | 把加权求和变回加权平均的分母，本节由 `z_t` 算出来 |
| KV Cache | 标准注意力推理时保存的每个历史词元的 K 和 V，可以按词元读取 |
| SSM | 状态空间模型。同样靠状态更新保存历史，但不走查询和键比较这条路 |

## 核心思路

输入是三排数：查询 `Q`、键 `K`、值 `V`，每个词元各占一行。线性注意力按时间步递推，每一步做三件事：

```text
S_t = S_{t-1} + φ(k_t) v_tᵀ           # 1. 更新：把当前词元的键和值累加进状态
z_t = z_{t-1} + φ(k_t)                 # 2. 更新：把当前词元的键累加进归一化项
o_t = (φ(q_t)ᵀ S_t) / (φ(q_t)ᵀ z_t)   # 3. 读取：用当前查询读状态，再除以分母
```

`t` 是时间步，`q_t`、`k_t`、`v_t` 是第 `t` 个词元的查询、键、值，`φ` 是正特征映射，`ᵀ` 表示转置。`S_t` 的形状是 `[feature_dim, value_dim]`，`z_t` 的形状是 `[feature_dim]`，两份状态都从全 0 开始。

用两个词元走一遍。键和查询是 2 维，值是 1 维：

```python
import numpy as np

def phi(x):                                   # TODO 1：教学用的正特征映射
    return np.maximum(x, 0.0) + 1.0

keys = [np.array([1.0, 0.0]), np.array([0.0, 1.0])]
values = [np.array([2.0]), np.array([4.0])]
q = phi(np.array([1.0, 0.0]))                 # 当前查询

state = np.zeros((2, 1))                      # S_0
normalizer = np.zeros(2)                      # z_0
for k, v in zip(keys, values):
    state = state + np.outer(phi(k), v)       # TODO 2
    normalizer = normalizer + phi(k)
    denominator = q @ normalizer              # TODO 3
    print(state.ravel(), normalizer, denominator, q @ state, (q @ state) / denominator)
```

```text
[4. 2.] [2. 1.] 5.0 [10.] [2.]
[ 8. 10.] [3. 3.] 9.0 [26.] [2.88888889]
```

每行依次是：状态 `S`、归一化项 `z`、分母、分子、输出。`phi` 把 `[1, 0]` 变成 `[2, 1]`，把 `[0, 1]` 变成 `[1, 2]`。第一步之后，`S` 是 `[4, 2]`，也就是 2 × 2 和 1 × 2。查询是 `[2, 1]`，分母是 2 × 2 + 1 × 1 = 5，分子是 2 × 4 + 1 × 2 = 10，输出是 2。第二步把第二个词元累加进去，`S` 变成 `[8, 10]`，输出是 26 / 9。

两个词元下来，`S` 的形状始终是 `[2, 1]`，`z` 的形状始终是 `[2]`。这就是“状态形状固定”。另外注意更新在读取之前：当前查询读到的是包含当前词元的状态，后面再来什么词元都影响不了这一步的输出。测试就是这样检查的，把最后一个词元的键和值各加 100，前面的输出不变。

## 容易踩的坑

- **特征映射会出现 0**：`φ` 的结果要严格大于 0，否则归一化项可能为 0，输出就没法除。参考写法是 `relu(x) + 1`。
- **更新和读取的顺序反了**：要先更新状态，再用当前查询读取。当前查询读的是本步更新后的历史状态。
- **状态形状跟着序列变**：`state` 始终是 `[feature_dim, value_dim]`，`normalizer` 始终是 `[feature_dim]`。两者都不随序列长度增长。
- **把测试通过当成和标准注意力等价**：测试只证明递推的因果性，不证明它和标准注意力数值等价。`relu(x) + 1` 也只是教学用的特征映射。
- **输入形状没对齐**：`queries` 和 `keys` 必须同形，并且和 `values` 共享非空的序列长度，否则要抛出 `ValueError`。
