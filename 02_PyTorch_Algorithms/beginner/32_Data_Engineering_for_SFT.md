## 一句话说清

准备用示范回答训练模型之前，这本 notebook 教你先给这批数据做体检：每条记录的字段齐不齐，训练集里有没有重复，有没有混进本来留作评测的题目。

## 为什么需要它

你已经决定用监督微调（SFT）训练模型，手里有一批“指令加标准回答”的示范数据。直接拿去训练之前，有三件事可能出错：

- 来源说不清。不知道每条数据从哪来、属于训练还是评测，出了问题没法回查。
- 重复的示范。同一个任务和回答出现两次，这类任务在训练里的比重就被悄悄放大了。
- 评测题混进训练。模型见过评测题，成绩再高也说明不了它对没见过的任务表现如何，这就是评测泄漏。

后两件事比看上去难查。notebook 的测试里有一条示范，换了编号、去掉了首尾空格，内容却和另一条一模一样，只比较编号发现不了它。另一个测试让两条示范题目相同、回答不同：这不算重复，但只要这道题留作评测，两条都算泄漏。

所以 notebook 的办法是给每条记录算两种“指纹”，分别去比：只含题目的一种拿来查评测泄漏，连回答一起的一种拿来查训练集重复。查完把通过的内容存一份副本，再拿去构造训练数据。

## 先认识几个词

| 词 | 人话解释 |
|:---|:---|
| 数据契约（data contract） | 对一条示范必须写清哪些内容的共同约定：身份、用途、题目和回答 |
| 切分（split） | 一条数据被划到的用途：训练、验证或测试 |
| 冻结评测集 | 预先固定成员和用途的验证或测试集合，里面的题目不进入训练 |
| 指纹（fingerprint） | 用来判断“两条内容是不是完全一样”的比较键，不是相似度分数 |
| 规范化 | 比较之前先统一写法，本例是去掉首尾空白、统一大小写 |
| 评测泄漏 | 本来留作评测的题目进入了训练，成绩说明不了模型对未见任务的表现 |
| 记录快照 | 审计通过时给这条内容留的独立副本，之后用它构造训练数据 |

## 核心思路

输入是一批候选示范，每条有样本编号、来源、切分、指令、上下文和回答。审计分三步：查字段，算两种指纹并比较，记下每条的决定和原因。

第一步，查字段，题目已经给出了 `assess_sft_contract`。编号、来源、切分不能为空，切分只能是 `train`、`validation` 或 `test`，指令和回答也不能为空。

第二步，算指纹（TODO 1）。Step 2 的公式写成纯文本是：

```text
f_task(x)    = (i(x), c(x))            任务输入指纹：只有指令和上下文
f_example(x) = (i(x), c(x), r(x))      完整样本指纹：再加上回答
```

`x` 是一条示范；`i(x)`、`c(x)`、`r(x)` 分别是规范化之后的指令、上下文和回答。两个指纹都是元组，可以直接用 `==` 比较。下面三条示范的前两条取自 notebook 的测试样例：

```python
def keys(instruction, context, response):
    i, c, r = (s.strip().casefold() for s in (instruction, context, response))
    return (i, c), (i, c, r)                  # 任务输入指纹，完整样本指纹

task_1, example_1 = keys(' 按三步处理退款请求 ', '订单已签收', ' 申请、核验、确认。 ')
task_2, example_2 = keys('按三步处理退款请求', '订单已签收', '申请、核验、确认。')
task_3, example_3 = keys('按三步处理退款请求', '订单已签收', '先核验，再退款。')
print(example_1 == example_2, example_1 == example_3)
print(task_1 == task_3)
```

```text

True
```

示范 1 和示范 2 只差首尾空格，规范化之后完整样本指纹相同，在训练集里算重复示范。示范 3 是同一道题换了回答：完整样本指纹不同，不算重复；可任务输入指纹和前面一样，只要这道题在冻结评测集里，它就是评测泄漏。

第三步，逐条记录原因（TODO 2）。一条记录可能同时命中几种风险，要分别判断、分别记。Step 3 的公式是：

```text
R(x) = R_contract(x) ∪ R_id(x) ∪ R_duplicate(x) ∪ R_leak(x)
A(x) = 1[R(x) 为空]        一个原因都没有，才准入
```

`R_contract` 是字段问题，`R_id` 是编号重复，`R_duplicate` 是完整样本重复，`R_leak` 是评测泄漏。通过审计的记录会存一份独立副本，训练数据从这份副本构造，而不是只记下编号再回候选池里查。

## 容易踩的坑

- **查泄漏时把回答也算进去**：泄漏检查只比较任务输入。混入回答的话，同一道题换个回答就逃过检查了。
- **只靠编号查重复**：换了编号的同一内容发现不了，训练集去重要比较完整样本指纹。
- **字段不全就跳过后面所有检查**：回答为空的记录仍然可能命中评测任务，能判断的风险要分别记录下来。
- **字段不全的记录占用了去重位置**：只有字段检查通过的记录才进入“已见”集合，否则后面的合法样本会被误判成重复。
- **只存准入编号再回候选池查**：同一个编号可能对应一条被拒的记录，回查会把它重新带回训练。要通过时保存内容副本。
