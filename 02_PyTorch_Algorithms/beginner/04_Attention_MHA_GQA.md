## 一句话说清

注意力让每个词元按“相关程度”汇总其他词元的信息。这本 notebook 实现多头注意力，并让多个头共用同一份历史记录（GQA、MQA），减少生成时要保存的内容。

## 为什么需要它

模型读一句话时，每个词元都要决定：该看前面哪些词元，各看多少。注意力做三件事：每个词元拿出一份查询（Q），和别人的键（K）比相似度得到分数；分数变成加起来等于 1 的权重；再按权重把它们的值（V）加起来。

把它写出来时，会遇到三个问题：

- **只有一副眼光**。只算一组 Q、K、V，每个词元只有一种比较方式。多头把向量拆成 `H` 份分别算，让模型从不同的表示子空间读取上下文。
- **历史越攒越多**。生成新词元时，前面词元的 K、V 都要留着。单层、单个词元的普通 K/V 状态元素数和 `2 × H_kv × D` 成正比，其中 `H_kv` 是 KV 头数，`D` 是每个头的宽度。`H = 8` 时，MHA 有 8 个 KV 头，是 `16 × D`；MQA 只有 1 个，是 `2 × D`。
- **头数对不上**。`H` 个查询头要平均分给 `H_kv` 个 KV 头，`H` 不能被 `H_kv` 整除就没法分。

这本 notebook 把这些写进同一个模块 `GroupedQueryAttention`：拆头、拼接缓存、算带掩码的注意力、合并输出。MHA、GQA、MQA 只差一个 `num_kv_heads` 参数。

## 先认识几个词

| 词 | 人话解释 |
|:---|:---|
| 查询 / 键 / 值（Query, Q / Key, K / Value, V） | 输入向量投影出来的三组向量。Q 用来查询相关位置，K 用来匹配位置，V 提供要被加权汇总的内容 |
| 注意力头 / KV 头 | 把向量拆成 `H` 份，每一份的查询叫一个注意力头。保存 K、V 的份数可以更少，叫 KV 头，个数记作 `H_kv` |
| 多头注意力 / 分组查询注意力 / 多查询注意力（MHA / GQA / MQA） | 三种头的组织方式：`H_kv = H`、`1 < H_kv < H`、`H_kv = 1`。后两种让几个查询头共用一组 K/V |
| 加性掩码 / 因果掩码（mask） | 加到分数上的张量：可见位置是 0，不可见位置是负无穷。因果掩码只允许看当前位置和之前的位置 |
| Softmax | 把一行分数变成加起来等于 1 的权重；负无穷的位置权重是 0 |
| `KV Cache` | 之前词元的 K 和 V 存起来，后面生成时接着读。它沿序列不断变长 |
| 预填充（prefill）/ 解码（decode） | 预填充是一次处理整段输入，查询数等于键数；解码是带着缓存一次生成一个词元，查询数是 1 |

## 核心思路

输入 `x` 的形状是 `[B, S, hidden_dim]`，每个词元一个向量。模块先把它投影成 Q、K、V，再走四步，最后输出形状和输入一样：

```text
拆头     xq 变成 [B, H, S, D]；xk、xv 变成 [B, H_kv, S, D]     # TODO 1
拼缓存   有历史时，把缓存的 K、V 接在当前 K、V 的前面           # TODO 2
算注意力 临时把 KV 头复制成 H 个，再算下面的公式                # TODO 3
合输出   [B, H, S, D] 变成 [B, S, H×D]，再过输出投影            # TODO 4
```

```text
scores = Q @ K^T / sqrt(D) + M       # [B, H, S_q, S_k]：每个查询对每个键的分数
probs  = softmax(scores, 沿最后一维)   # 每一行加起来是 1
output = probs @ V                    # [B, H, S_q, D]：按权重把 V 加起来
```

公式按单个查询头计算。符号说明：`K^T` 是转置；`D` 是每个头的特征宽度（`head_dim`），除以 `sqrt(D)` 叫缩放；`M` 是加性掩码；`S_q` 是当前查询词元数，`S_k` 是包含历史在内的键词元数。

MHA、GQA、MQA 用的是同一个模块，只是 `H_kv` 不同。GQA 和 MQA 里，每个 KV 头分到 `H / H_kv` 个查询头，所以算注意力前要临时把 KV 头复制成 `H` 个。复制只发生在当前这次计算里：存进缓存的是没复制的 K、V，缓存才不会被放大到 MHA 的大小。Step 2 还提到 MLA，它改变的是缓存内容，这本 notebook 不实现。

下面用很小的数看三个关键点：掩码、复制 KV 头、拼接缓存：

```python
import torch

# 1) 因果掩码：2 个查询看 3 个键，-inf 表示看不见
scores = torch.tensor([[0., 1., 2.], [3., 4., 5.]])       # 2 个查询对 3 个键的分数
mask = torch.tensor([[0., float('-inf'), float('-inf')],
                     [0., 0., float('-inf')]])             # 只能看当前位置和之前
v = torch.tensor([[1., 0.], [0., 1.], [9., 9.]])
probs = torch.softmax(scores + mask, dim=-1)
print(probs)
print(probs @ v)                                          # 第 3 个词元的 V 没起作用

# 2) GQA：2 个 KV 头，每个复制给 2 个查询头
def repeat_kv(x, n_rep):
    b, h, s, d = x.shape
    return x.unsqueeze(2).expand(b, h, n_rep, s, d).reshape(b, h * n_rep, s, d)

kv = torch.arange(2.).reshape(1, 2, 1, 1)                 # [B=1, H_kv=2, S=1, D=1]
kv4 = repeat_kv(kv, 2)
print(tuple(kv.shape), tuple(kv4.shape))
print(kv4.flatten())

# 3) 缓存：历史在前，当前在后，沿序列维拼接
k_cache = torch.tensor([[[[10.], [20.]]]])                # [1, 1, 2, 1]：2 个历史位置
k_now = torch.tensor([[[[30.]]]])                         # [1, 1, 1, 1]：当前 1 个位置
print(torch.cat([k_cache, k_now], dim=2).flatten())
```

```text
tensor([[1.0000, 0.0000, 0.0000],
        [0.2689, 0.7311, 0.0000]])
tensor([[1.0000, 0.0000],
        [0.2689, 0.7311]])
(1, 2, 1, 1) (1, 4, 1, 1)
tensor([0., 0., 1., 1.])
tensor([10., 20., 30.])
```

第 1 部分：第 1 个词元只能看自己，权重是 `1.0000`；第 2 个词元看前两个，权重是 `0.2689` 和 `0.7311`。第 3 个词元的 V 是 `[9, 9]`，但权重是 0，输出里看不到它。第 2 部分：2 个 KV 头 `[0, 1]` 复制后变成 `[0, 0, 1, 1]`，前两个查询头读第一个 KV 头，后两个读第二个。第 3 部分：历史位置 `[10, 20]` 在前，当前位置 `30` 在后。

## 容易踩的坑

- **把复制后的 K/V 存进缓存**：缓存里始终保留 `H_kv` 个 KV 头，查询共享只在当前注意力计算时展开。复制结果写回缓存，就失去了 GQA 的显存优势。
- **沿错了维度拼接**：历史状态沿序列维追加，历史在前、当前在后。在 `[B, H_kv, S, D]` 里，序列维是从 0 数的第 2 维。
- **掩码没加或者加晚了**：`attention_mask` 是加性掩码，要加到分数上再做 Softmax，并且能广播到 `[B, H, S_q, S_k]`。不加掩码，当前位置就能读到未来词元。
- **合并输出时直接压平**：要从 `[B, H, S, D]` 恢复成 `[B, S, H×D]`，每个词元的 `H` 个头接在一起。直接 `reshape` 会把不同词元的数混到一起，先把头轴换到序列轴后面再压平。
- **头数不能整除**：`hidden_dim` 要能被 `num_heads` 整除，`num_heads` 要能被 `num_kv_heads` 整除，否则构造函数直接报错。
