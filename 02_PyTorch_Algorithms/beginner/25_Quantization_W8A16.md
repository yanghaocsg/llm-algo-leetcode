## 一句话说清

量化是把模型权重从小数换成“小整数加一个缩放因子”来保存。这本 notebook 带你手写一个用 8 位整数存权重的线性层，并看清它省在哪里、不省在哪里。

## 为什么需要它

线性层里有一张权重表，平时每个权重用小数保存：`float32` 每个数 4 个字节，`int8` 只要 1 个字节（下面的小例子用 `element_size()` 查过）。所以一个直接的想法是把权重换成 8 位整数来存。

但换完之后有三件事要处理：

- 整数不是原来的权重。存进去的是 127 这样的数，它代表多少，要靠缩放因子来说明。只存整数，权重就还原不回来。
- 一批权重里有个特别大的数。如果整批共用一个缩放因子，其他小数只能挤在少数几个整数上，还原时误差变大。
- 存得小不等于算得快。用之前要把整数变回小数，这一步放在哪里做，决定了省下的存储能不能变成速度上的收益。

量化（quantization）的做法是：小数除以缩放因子、取整，存成整数，用的时候再乘回去。这本 notebook 只管表示这一层：怎样算缩放因子和零点，它们由多少个权重共用。

## 先认识几个词

| 词 | 人话解释 |
|:---|:---|
| 整数码（integer code） | 代替浮点权重保存的那个整数，比如 127，只能取码值范围内的值 |
| 缩放因子（scale） | 一个整数格代表多少小数。整数码乘它，就回到原来的大小 |
| 零点（zero point） | 代表实数 0 的那个整数。对称量化里固定是 0，非对称量化里可能是别的码值 |
| 反量化（dequantization） | 用的时候把整数码变回小数，得到的是原权重的近似值 |
| 粒度（granularity） | 多少个权重共用一组缩放因子和零点：整个张量、每个输出通道，或者每个分组 |
| 量化参数（qparam） | 缩放因子和零点的合称，要跟着整数码一起保存 |
| 缓冲区（buffer） | 模块里跟着保存、但不是可训练参数的张量。本题的 INT8 权重、缩放因子和零点都是缓冲区 |

## 核心思路

输入是一批浮点权重。先找出最大绝对值（非对称时是最小值和最大值），算出缩放因子。再把每个权重除以缩放因子，四舍五入并截到码值范围内，得到整数码。保存时整数码用 `int8`，缩放因子和零点用 `float32`，它们合起来就是量化状态。

notebook 把前两步写成了公式，这里是纯文本版：

```text
对称：   s = max|x_i| / q_max
         q_i = clip(round(x_i / s), q_min, q_max)          x_hat_i = s * q_i

非对称： s = (x_max - x_min) / (q_max - q_min)
         z = clip(round(q_min - x_min / s), q_min, q_max)
         q_i = clip(round(x_i / s + z), q_min, q_max)      x_hat_i = s * (q_i - z)
```

`x_i` 是浮点权重，`q_i` 是整数码，`s` 是缩放因子，`z` 是零点，`x_hat_i` 是恢复出的近似值。码值范围 `q_min` 到 `q_max` 是整数码能取的区间：对称取 -127 到 127，非对称取 -128 到 127，每个可取的整数叫一个码点。下面把全正的片段 `[1.0, 3.0]` 用两种方式各量化一次，再量化一行里面有个特别大的数的权重；函数返回整数码、缩放因子、零点、恢复值。

```python
import torch
torch.set_printoptions(precision=6)

def quant(x, symmetric=True):
    if symmetric:                                   # 零点是 0，码值范围 [-127, 127]
        scale, zero, qmin, qmax = x.abs().max() / 127, torch.tensor(0.), -127, 127
    else:                                           # 先把 0 纳入范围，码值范围 [-128, 127]
        lo = torch.minimum(x.min(), torch.tensor(0.))
        hi = torch.maximum(x.max(), torch.tensor(0.))
        scale, qmin, qmax = (hi - lo) / 255, -128, 127
        zero = torch.round(qmin - lo / scale)
    code = torch.clamp(torch.round(x / scale + zero), qmin, qmax)
    return code, scale, zero, scale * (code - zero)

x = torch.tensor([1.0, 3.0])                        # 一个全正的权重片段
print("对称  ", quant(x))
print("非对称", quant(x, symmetric=False))
row = torch.tensor([0.1, 0.2, 5.0, 6.0])            # 一行权重，后两个数特别大
print("整行一组", quant(row)[3])
print("切成两组", quant(row[:2])[3], quant(row[2:])[3])
print((5 + 2 - 1) // 2,                             # 5 个输入、每组 2 个，要分几组
      torch.tensor([1.0]).element_size(), torch.tensor([1], dtype=torch.int8).element_size())
```

```text
对称   (tensor([ 42., 127.]), tensor(0.023622), tensor(0.), tensor([0.992126, 3.000000]))
非对称 (tensor([-43., 127.]), tensor(0.011765), tensor(-128.), tensor([1., 3.]))
整行一组 tensor([0.094488, 0.188976, 5.007874, 6.000000])
切成两组 tensor([0.100787, 0.200000]) tensor([5.007874, 6.000000])
3 4 1
```

看三处：

- 对称量化：零点是 0，整数码是 42 和 127，负数那一半码点用不上，1.0 只能恢复成 0.992126。
- 非对称量化：范围先扩大到包含 0，零点变成 -128，两个数都能恢复成原值，代价是多保存一个零点。
- 粒度：整行共用一个缩放因子时，0.1 和 0.2 被恢复成 0.094488 和 0.188976；切成两组后恢复成 0.100787 和 0.2。范围越小，局部误差通常更低，缩放因子也更多。缩放因子的个数：逐张量 1 个，逐通道 `out_features` 个，逐组 `out_features × ceil(in_features / group_size)` 个。

最后一行的 3 是分组数：5 个输入、每组 2 个，尾部不足一组也要占一组；4 和 1 是两种类型每个数占的字节数。

用的时候，教学前向先把整数码恢复成和输入同类型的浮点权重，再做线性计算。这对应 notebook 表格里的 eager dequantization 路径：能证明表示、误差和状态账本，不能推出量化计算内核加速。名字里的 W8 表示权重以 8 位保存，A16 表示激活采用 16 位格式，它只是表示约定，不自动等于纯整数执行。

## 容易踩的坑

- **缩放因子算成了 0**：全零张量的绝对最大值是 0，缩放因子跟着变成 0。要用 `eps`（默认 `1e-8`）给它一个正的下限，非对称量化遇到常量张量同理。
- **非对称量化没有先把 0 纳入范围**：只用全正数据的两个端点，零点裁剪后可能让端部的数值饱和。先取 `x_min = min(0, 最小值)` 和 `x_max = max(0, 最大值)`，再算缩放因子。
- **分组数向下取整**：5 个输入、每组 2 个需要 3 组。少算一组，尾部的权重就没有量化状态。
- **前向时改了保存的状态或弄错数据类型**：恢复的权重和偏置都要转成输入的 `dtype`，`weight_int8`、`scale`、`zero_point` 这三个缓冲区保持不动。
- **把“权重更小”当成“算得更快”**：W8A16 只是表示约定，不自动等于纯整数执行。教学前向不能推出量化计算内核加速。
