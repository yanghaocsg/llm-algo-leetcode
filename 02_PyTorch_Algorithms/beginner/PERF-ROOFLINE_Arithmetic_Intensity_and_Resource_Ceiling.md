## 一句话说清

一次矩阵乘法慢，可能是搬数据慢，也可能是算得慢。这本 notebook 教你先算“每搬 1 字节做多少次运算”，再判断这次运算卡在哪一种限制上。

## 为什么需要它

你测了一次矩阵乘法，比预期慢。想优化，先得知道时间花在哪：是在搬数据，还是在做计算？方向猜错了，改了也没有用。

决定因素是“每搬 1 字节，能做多少次运算”。notebook 测试里有一个很小的矩阵乘法：`A` 是 2×4，`B` 是 4×3，每个元素 2 字节。它大约要做 48 次浮点运算，却至少要搬 52 字节，也就是每搬 1 字节只做 0.92 次运算（下面的代码会算出来）。这种“搬得多、算得少”的运算，容易卡在搬数据上。反过来，矩阵很大时复用多，容易卡在计算上。

没有一把统一的尺子，容易出三种问题：

- 只凭实测时间猜瓶颈，说不出依据。
- 拿一次矩阵乘法量出来的速度当作机器的硬上限，之后看到别的算子“超过了上限”，就把比值截到 1。
- 把模型估出来的搬运量，当成机器实际搬了多少数据。

这本 notebook 用屋顶线模型把两种限制放到同一张图上：先从矩阵形状算出运算量、最低搬运量和算术强度，再和机器的两个参考值比较，判断落在哪一侧，离参考还差多少。

## 先认识几个词

| 词 | 人话解释 |
|:---|:---|
| FLOPs | 浮点运算次数。notebook 里一次乘法算一次，一次加法算一次 |
| 最低搬运量（`minimum_bytes`） | 完成这次运算至少要搬多少字节：两个输入各读一次，输出写一次 |
| 算术强度（arithmetic intensity） | 运算量除以搬运量，单位 FLOPs/Byte，意思是“每搬 1 字节能做多少次运算” |
| 计算吞吐上界（`peak_flops`）/ 带宽（`bandwidth_bytes_per_s`） | 机器每秒最多算多少次 / 每秒最多搬多少字节 |
| 机器平衡点（`machine_balance`） | 计算吞吐除以带宽，是算术强度的分界线。低于它落在带宽侧（`bandwidth_bound`），等于或高于它落在计算侧（`compute_bound`） |
| 理想上界 / 经验参考 | 理想上界是严格的上限；经验参考是用本机一次复制和一次矩阵乘法量出来的代替值，可以被超过 |
| 相对吞吐（`roofline_efficiency`） | 实测吞吐除以屋顶线给出的上界，1 表示正好达到上界 |

## 核心思路

输入是矩阵维度 `m`、`n`、`k`，每个元素的字节数 `dtype_bytes`，再加上机器的计算吞吐上界 `peak_flops` 和带宽 `bandwidth_bytes_per_s`。TODO 1 从形状算出运算量、最低搬运量和算术强度。TODO 2 用算术强度乘以带宽，再和计算吞吐上界取较小值，得到这次运算的吞吐上界，并贴上带宽侧或计算侧的标签。TODO 3 用实测吞吐除以这个上界，得到相对吞吐；超过 1 时不截断，只加上复核提示。输出是一份报告，里面有算术强度、所在区间、上界、实测吞吐、相对吞吐和复核提示。

```text
F     ≈ 2 * m * n * k                 # 运算量：每个输出元素约 k 次乘加
Q_min = d * (m*k + k*n + m*n)         # 最低搬运量：A、B 各读一次，C 写一次
I     = F / Q_min                     # 算术强度

R(I)  = min(P, I * B)                 # 吞吐上界：两个限制取较小值
I_*   = P / B                         # 机器平衡点
T    >= max(F / P, Q / B)             # 执行时间的下限

eta   = P_meas / R(I)                 # 相对吞吐，P_meas = F / 实测时间
```

`A` 是 `m×k`，`B` 是 `k×n`，输出 `C` 是 `m×n`；`d` 是每个元素的字节数；`F` 是运算量，`Q_min` 是最低搬运量，`I` 是算术强度；`P` 是计算吞吐上界，`B` 是带宽；`R(I)` 是算术强度为 `I` 时的吞吐上界，`I_*` 是机器平衡点；`T` 是执行时间，`eta` 是相对吞吐。

下面用测试里的小矩阵算一遍。机器的两个数是编的，方便心算，单位只要前后一致就行。

```python
def workload(m, n, k, d):                       # d 是每个元素的字节数
    flops = 2 * m * n * k                       # 乘法和加法各算一次
    moved = d * (m * k + k * n + m * n)         # 两个输入各读一次，输出写一次
    return flops, moved, flops / moved

P, B = 1000.0, 100.0                            # 计算吞吐上界、带宽（数字是编的）
flops, moved, I = workload(2, 3, 4, 2)
print(flops, moved, I)
print(flops / P, moved / B, P / B)              # 纯计算时间、纯搬运时间、平衡点
for I in (I, 20.0):
    bound = min(P, I * B)
    print(I, bound, "bandwidth_bound" if I * B < P else "compute_bound")
bound = min(P, 48 / 52 * B)
print(60.0 / bound, 150.0 / bound, 150.0 / bound > 1.0)
```

```text
48 52 0.9230769230769231
0.048 0.52 10.0
0.9230769230769231 92.3076923076923 bandwidth_bound
20.0 1000.0 compute_bound
0.65 1.625 True
```

这个矩阵乘法的强度约 0.92，比平衡点 10 低，所以落在带宽侧：吞吐上界是 0.92 × 100 ≈ 92.3，而不是 1000。纯计算只要 0.048 秒，纯搬运要 0.52 秒，时间下限取两者中较大的那个。把强度换成 20，高于平衡点，上界就变成计算吞吐 1000，落在计算侧。图上“强度乘带宽”是一条斜线，“计算吞吐”是一条水平平台，合起来像屋顶的侧面；对应到本节，斜线是带宽限制，平台是计算限制。

最后看相对吞吐：实测 60 时比值是 0.65；实测 150 时比值是 1.625，比上界还高。notebook 的做法是保留 1.625 并返回复核提示，不把它截成 1。

## 容易踩的坑

- **把运算次数当成搬运量**：字节模型只累加两个输入和一个输出，和运算量是两回事。两者分开算，再相除得到强度。
- **把模型强度当成实际流量**：模型假设每个输入只读一次，真实流量可能因重复读取而增加，也可能因缓存命中而减少。不同存储层的带宽也不能混用。
- **平衡点贴错标签**：强度乘带宽正好等于计算吞吐时，notebook 约定归入计算侧。这只是标签约定，不代表带宽限制消失了。
- **把比值截到 1**：相对吞吐大于 1 时要保留原值，并返回复核提示。截断会掩盖经验参考不够高或测量条件不一致的问题。
- **接受布尔值或非法数**：Python 里 `True` 算整数，维度和元素字节数必须单独排除它，并要求是正整数；强度、计算吞吐和带宽必须是有限正数。
