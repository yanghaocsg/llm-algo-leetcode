## 一句话说清

FP8 是只用 8 个二进制位保存小数的格式。这本 notebook 教你把一组数缩放进 FP8 的表示范围，并判断一次计算是否真的用上了 FP8。

## 为什么需要它

权重量化改变的是参数的保存与读取方式。FP8 运行时路径走得更远：输入激活、权重、累加和输出这四个位置的数据类型组合都变掉，最好由硬件直接用 FP8 做矩阵乘法。激活（activation）是进入某一层算子的那份输入，累加（accumulation）是矩阵乘法里把许多乘积加在一起的那一步。

收益不会自动出现：

- 分不清计算是怎么发生的。把权重存成 FP8，不等于激活也以 FP8 进入计算，更不等于硬件执行了原生计算内核。框架能创建 FP8 数据类型，也只说明表示和接口可用。
- FP8 能表示的范围很窄。E4M3 最大只能表示 448，更大的数放不进去，要靠缩放因子把整个张量挪进格式的范围。

这本 notebook 在 CPU 上把两件事各做一遍：用缩放因子把张量映射到格式的有限范围；把“数据是什么格式”和“计算实际怎样执行”分开记录。

## 先认识几个词

| 词 | 人话解释 |
|:---|:---|
| FP8 | 只用 8 个二进制位保存一个数的浮点格式 |
| E4M3 / E5M2 | 两种 FP8 格式。E 后面的数字是指数位的个数，M 后面的数字是尾数位的个数 |
| 指数位 / 尾数位（exponent / mantissa） | 指数位决定一个数落在哪个大小区间，尾数位决定区间内部切成多细的格 |
| 最大有限值（`f_max`） | 一种格式能表示的最大的数。这里的 E4M3 是 448，E5M2 是 57344 |
| 绝对最大值（absmax） | 一组数里不看正负号、最大的那个，记作 `a`。比如 `[-7, 0, 3.5]` 的绝对最大值是 7 |
| 恢复尺度（scale） | 编码前除以它、恢复时乘回它的那个数，记作 `s` |
| 原生计算内核（native kernel） | 由硬件直接以 FP8 执行计算的那段程序。只有它真的执行了，才能说发生了 FP8 计算 |

## 核心思路

把张量 `x` 存成 FP8，再恢复成高精度的近似值，分三步：

```text
s     = max(a / f_max, eps)      # 1. 算出恢复尺度
x_fp8 = cast_fp8(x / s)          # 2. 编码：先除以 s，再转成 FP8
x_hat = s * cast_high(x_fp8)     # 3. 恢复：转回高精度，再乘回 s
```

`a` 是绝对最大值，`f_max` 是格式的最大有限值，`eps` 是很小的正数（题目里默认 `1e-8`），防止全零张量算出零尺度。`a` 的来源决定缩放的种类：静态缩放用固定校准集，动态缩放用当前张量，延迟缩放用历史窗口。TODO 1 做的是动态缩放。

“转成 FP8”这一步，题目区用教学化的舍入网格模拟，不需要 FP8 硬件。先取指数 `e`：对缩放后的值以 2 为底取对数再向下取整，它说明这个数落在哪一段。段内的步长是 `2^(e - 尾数位数)`，尾数位越多，格子越细。

下面用小数字走一遍：

```python
import torch

# 第 1 步：动态缩放。E4M3 的最大有限值是 448
x = torch.tensor([-7.0, 0.0, 3.5])
s = (x.abs().max() / 448.0).clamp_min(1e-8)   # 恢复尺度
print(s.item())
print((x / s).tolist())                        # 除以 s：最大的值刚好贴到 448
print((x / s * s).tolist())                    # 乘回 s：恢复原值

# 第 2 步：在缩放后的空间里，按尾数位数舍入
scaled = torch.tensor([448.0, 1.1, 0.35])      # 第二个张量
print((scaled.abs().max() / 448.0).clamp_min(1e-8).item())   # 它的恢复尺度
exponent = torch.floor(torch.log2(scaled.abs()))
print(exponent.tolist())
for name, bits in [("e4m3", 3), ("e5m2", 2)]:
    step = 2.0 ** (exponent - bits)            # 每个区间切成 2^bits 格
    rounded = torch.round(scaled / step) * step
    print(name, step.tolist(), rounded.tolist())
```

```text
0.015625
[-448.0, 0.0, 224.0]
[-7.0, 0.0, 3.5]
1.0
[8.0, 0.0, -2.0]
e4m3 [32.0, 0.125, 0.03125] [448.0, 1.125, 0.34375]
e5m2 [64.0, 0.25, 0.0625] [448.0, 1.0, 0.375]
```

第一个张量的绝对最大值是 7，恢复尺度是 0.015625：除以它以后最大的数刚好贴到 448，乘回去就恢复原值。第二个张量的绝对最大值正好是 448，恢复尺度是 1。指数 `[8, 0, -2]` 说明 448 落在 256 到 512 之间，1.1 落在 1 到 2 之间，0.35 落在 0.25 到 0.5 之间。同样是 1.1，E4M3 把它挪到 1.125，E5M2 把它挪到 1.0。E5M2 少一位尾数，每段的步长都是 E4M3 的 2 倍；它换来的是指数多一位，能表示到 57344。

另外两点。比最小正规数还小的值落在次正规数（subnormal）区间，那里的步长固定，更小的值会舍入到零。TODO 3 不运行任何计算，只根据外面传进来的三个条件给证据选一个状态：

## 容易踩的坑

- **把缩放的方向写反了**：恢复尺度是“绝对最大值 ÷ 最大有限值”，编码前除以它，恢复时乘回它。有些框架保存的是它的倒数，读取字段前要先核对约定。
- **全零输入得到零尺度**：绝对最大值是 0 时，要用 `eps` 给尺度一个正下限。
- **把两种格式当成一回事**：这里的 E4M3 指最大有限值为 448 的 E4M3FN，E5M2 的最大有限值是 57344，不能只凭名称互换。
- **次正规区间还让步长继续变小**：那里的步长固定为最小步长，更小的值舍入到零。
- **数据类型可用就说用了 FP8 计算**：只有 CUDA 设备、目标数据类型、原生计算内核三个条件同时满足，才是 `native_fp8_kernel`，否则只能记录回退路径。
