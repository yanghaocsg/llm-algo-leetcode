## 一句话说清

LoRA 微调的秩怎么选？这本 notebook 教你一套选法：固定其他条件，逐项检查质量和资源，用相同随机种子比较损失差，再选代价更低的配置。

## 为什么需要它

用 LoRA 微调，先要定秩。秩越大，可训练的参数越多。但 notebook 一开头就提醒：在当前数据和训练步数下，参数多不保证回答更好。

真要比较几种秩，很容易掉进三个坑：

- 一次改了多处。你把秩从 8 改成 16，顺手换了目标层，评测损失降了。是秩的功劳，还是目标层的功劳？说不清。
- 差距太小，可能只是运气。两份配置在同一个随机种子下的评测损失是 1.20 和 1.18，换一个种子，谁低谁高可能就反过来。
- 只看损失，忘了资源。测试样例里，`rank16` 的评测损失最低（1.10），但峰值分配显存 3500 超过了预算 3000，照样要排除。

这本 notebook 解决的是“怎样选”：先确认几份配置真的可比，再逐项检查每次运行的质量和资源，然后用共享种子比较损失差。损失差不超出允许范围时，选显存和步时更低的那个。

## 先认识几个词

| 词 | 人话解释 |
|:---|:---|
| 秩（rank） | LoRA 新增的那条低秩分支有多宽；秩越大，可训练参数越多 |
| 缩放系数 `alpha / r` | 低秩分支的输出要乘的一个系数，`r` 是秩。`alpha` 固定为 16 时，秩 4、8、16 对应 4、2、1 |
| 基线 / 候选 | 基线是拿来对照的那份配置，候选是你要比较的另一份（如 `rank16`） |
| 随机种子（seed） | 决定随机序列起点的整数。配对就是让两份运行用同一个种子 |
| 配对损失差 | 同一种子下两份运行的损失先相减，再对这些差取中位数（排序后中间那个数） |
| 峰值分配显存 / 步时 / 监督词元吞吐 | 三项资源指标：最多占了多少显存、一步训练用多久、每秒处理多少个要学的词元 |
| `accept` / `tune` / `reject` | 决策的三种结果：采用、补测或修复后再选、拒绝 |

## 核心思路

输入是基线配置、每份候选的摘要、按种子记录的多次运行结果，以及一组门槛。骨架代码已经写好了输入校验、逐次门槛、配对和排序，你补三处判断。输出是一个决定和一个选中的配置。

```text
可比性检查 → 逐项门槛 → 配对与波动检查 → 配对损失差 → 比显存、步时 → accept
```

notebook 里有三个式子，写成纯文本是：

```text
缩放系数          s = alpha / r
样本平均评测损失    = (1 / M) * Σ (S_i / N_i)
质量等价  <=>  |配对损失差| <= 允许偏差
```

`alpha` 是缩放超参数，`r` 是秩。`M` 是评测样本总数，`S_i` 是第 `i` 条样本的损失总和，`N_i` 是它的有效目标数，`Σ` 是求和。`<=>` 读作“当且仅当”。

第二个式子的意思是：先在每条样本内部按词元平均，再让每条样本权重相同。它和 13、15 节的全词元平均不一样。两条回答分别有 2 个和 6 个目标，平均损失是 1 和 3，本项目的指标是 2，全词元平均是 2.5。比较候选必须用同一种算法和同一批评测样本。

第三个式子最容易做错。看一个小例子：

```python
import statistics

alpha = 16
print([alpha / r for r in (4, 8, 16)])   # 秩 4、8、16 对应的缩放系数

# 同一组种子下，两份候选各自的评测损失
loss_a = {11: 1.20, 29: 1.21}
loss_b = {11: 1.18, 29: 1.19}
deltas = [loss_b[s] - loss_a[s] for s in sorted(loss_a)]
print([round(d, 4) for d in deltas], round(statistics.median(deltas), 4),
      abs(statistics.median(deltas)) <= 0.03)   # 允许偏差是 0.03

# 反例：逐种子差的中位数，不等于两个中位数之差
x, y = [0, 0, 2], [0, 1, 1]
pair = [b - a for a, b in zip(x, y)]
print(pair, statistics.median(pair), statistics.median(y) - statistics.median(x))
```

```text
[4.0, 2.0, 1.0]
[-0.02, -0.02] -0.02 True
[0, 1, -1] 0 1
```

`loss_a` 和 `loss_b` 是两份候选在同两个种子下的评测损失。每个种子上的差都是 -0.02，中位数也是 -0.02，绝对值没有超过允许的 0.03，所以这两份候选算“质量等价”，接下来比显存和步时。最后一行是解析里的反例：逐种子相减再取中位数得 0，两个中位数相减却得 1。两种算法不是一回事，TODO 3 要的是前一种。

## 容易踩的坑

- **只检查了表里的字段**：候选可比要同时满足三条：固定字段没变、恰好一个声明的候选字段变了、其他字段也没变。测试在改秩的同时把最大长度从 256 改成 512，不能因为表内只变了秩就放行。
- **用质量抵消显存超限**：运行成功、损失和显存不超过上限、吞吐不低于下限，四项必须同时成立。质量最好的候选仍可能因显存超限被排除，门槛不合成加权总分。
- **摘要通过就跳过原始运行**：每次重复都要再过一遍同样的检查。即使候选摘要合格，某一次的损失或资源不达标，这个候选也会被排除。
- **把两个中位数相减当成配对损失差**：正确顺序是先按同一种子相减，再取中位数，最后比较绝对值。等号算在允许范围之内。
- **把“质量等价”想多了**：它只是说配对损失差满足这条数值规则，不是统计检验，也不代表所有任务上质量相同。短预算下的排名也不能外推到更长训练。
