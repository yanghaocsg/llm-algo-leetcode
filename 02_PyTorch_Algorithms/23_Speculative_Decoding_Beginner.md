## 一句话说清

大模型生成文字，通常每跑一遍只能吐出一个词。这本 notebook 教一种可能提速的办法：先让小模型连续猜几个词，再让大模型一次检查，能接受的留下，不能接受的就地改对。

## 为什么需要它

模型生成文字是一个词一个词往外冒的：大模型每推进一个词元，都要跑一遍。想快一点，一条路是让大模型每跑一遍能多推进几个词元。

投机解码（speculative decoding）的做法是请一个成本低的小模型先猜。小模型连续猜出几个候选词元，大模型再把这几个位置一次性检查一遍。结果有三种：

- 某个候选被接受：把它提交到最终序列，接着检查下一个。
- 某个候选被拒绝：本轮立刻结束，在这个位置换上一个修正词元，后面的候选全部作废。
- 全部候选都被接受：大模型这次检查还多看了一个位置，可以再多得一个词元。

最要紧的一点是，最后的输出仍然要服从大模型自己的概率，不能因为让小模型先猜就变了。所以“按什么概率接受”和“拒绝了怎么改”都有严格的算法。它也不一定更快：草稿和验证本身有额外成本，是否真正加速要由这些成本一起决定。Step 1–4 的 CPU 题目不跑真实模型，直接给出两个模型在每个位置上的概率，让你把单轮的接受、修正和追加写出来。

## 先认识几个词

| 词 | 人话解释 |
|:---|:---|
| 草稿模型（draft model） | 成本低的小模型，负责连续提出候选词元，同时给出它在每个位置的概率 |
| 目标模型（target model） | 真正想要它输出的大模型，负责验证候选，同时给出它在每个位置的概率 |
| 草稿分布 `q`、目标分布 `p` | 同一个位置上，草稿模型和目标模型各自给出的词表概率，各自加起来等于 1 |
| 候选 `x` | 草稿模型实际提出的词元。一轮有 `K` 个，按顺序编号 |
| 接受概率 `α` | 候选被目标模型接受的机会，是 `p(x) / q(x)` 和 1 中较小的那个 |
| 正残差分布 `r` | 只保留目标概率比草稿概率高出来的部分，再归一化。拒绝时从这里抽修正词元 |
| 追加 Token（bonus） | 全部候选被接受后，从额外目标位置多采样的一个词元 |

## 核心思路

输入是两张按位置对齐的概率表：草稿概率 `draft_probs`，形状 `[K, vocab]`；目标概率 `target_probs`，形状 `[K + 1, vocab]`，多出来的一行是全部接受后用的额外位置。另外还有草稿实际提出的 `K` 个词元 `draft_tokens`。程序从左往右逐个检查：

```text
对第 i 个候选 x（i 从 0 到 K - 1）：
  α = min(1, p_i(x) / q_i(x))      # 接受概率
  抽一个 0 到 1 之间的随机数：
    随机数 < α  → 接受：提交 x，继续检查下一个候选
    随机数 ≥ α  → 拒绝：本轮结束，输出“已接受的词元 + 一个修正词元”
K 个全部接受 → 再从 target_probs 下标为 K 的那一行（第 K + 1 个位置）抽一个追加词元

修正词元从正残差分布里抽：r(v) = max(p(v) - q(v), 0) / sum_u max(p(u) - q(u), 0)
```

`p_i`、`q_i` 是第 `i` 个位置的目标分布和草稿分布；`x` 是这个位置上的候选词元；`v` 和 `u` 都遍历词表里的每个词元。`max(·, 0)` 把负数截成 0，所以只有目标概率高于草稿概率的词元才会留在修正分布里。“提交”指把词元纳入最终生成的序列，不是把整段草稿交给用户。

看 notebook Step 3 的例子：某个位置上草稿概率 `q = (0.8, 0.2)`，目标概率 `p = (0.4, 0.6)`，词表里只有 2 个词元。

```python
import torch

q = torch.tensor([0.8, 0.2])                 # 草稿模型在某个位置给出的概率
p = torch.tensor([0.4, 0.6])                 # 目标模型在同一位置给出的概率

alpha = torch.minimum(torch.ones(2), p / q)  # 每个词元的接受概率
residual = torch.clamp(p - q, min=0)
residual = residual / residual.sum()         # 拒绝时用的修正分布
print(alpha)
print(residual)

accepted = q * alpha                         # 每个词元被直接接受的概率
rejected = 1 - accepted.sum()                # 被拒绝的总概率
print(accepted, rejected)
print(accepted + rejected * residual)        # 最终每个词元出现的概率
print(accepted + rejected * p)               # 如果拒绝后直接从目标分布重新采样
```

```text
tensor([0.5000, 1.0000])
tensor([0., 1.])
tensor([0.4000, 0.2000]) tensor(0.4000)
tensor([0.4000, 0.6000])
tensor([0.5600, 0.4400])
```

第一行是两个词元的接受概率，0.5 和 1。第二行是修正分布：第一个词元的目标概率不比草稿高，差值被截成 0，所以拒绝后只能改成第二个词元。第三行是概率账本：第一个词元被直接接受的概率是 `0.8 × 0.5`，第二个是 `0.2 × 1`，被拒绝的总概率是剩下的 0.4。第四行把直接接受和拒绝修正两部分合起来，正好是目标分布 `(0.4, 0.6)`。第五行是反例：如果拒绝后直接从目标分布重新采样，结果变成 `(0.56, 0.44)`，不再是目标分布。

上面说的是随机采样的规则。贪心路径不同，它逐位置核对候选是不是目标分布里分数最大的词元。

## 容易踩的坑

- **`q` 等于 0 时直接相除**：候选正常是从草稿分布采出来的，`q(x)` 大于 0。但辅助函数要能处理 `q` 为 0 的情况：`p` 大于 0 时接受概率是 1，否则是 0，不能发生除零。
- **接受概率超过了 1**：`p / q` 可能大于 1，要截断到 1，接受概率必须落在 0 到 1 之间。
- **修正分布保留了负的差值**：只保留目标概率超过草稿概率的部分，也就是 `max(p - q, 0)`，再归一化。全部为 0 时必须报错。拒绝后直接从目标分布重新采样，会改变结果分布。
- **拒绝后还继续检查后面的候选**：首次拒绝立即关闭后缀，后面的候选不能再进入本轮输出，函数直接返回“已接受的词元 + 修正词元”。
- **追加词元复用了最后一个验证位置**：全部接受后，追加词元要从额外的第 `K + 1` 个目标位置采样，也就是 `target_probs` 下标为 `K` 的那一行。
