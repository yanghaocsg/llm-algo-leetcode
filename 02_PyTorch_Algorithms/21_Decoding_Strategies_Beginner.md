## 一句话说清

模型生成文字时，每一步都给词表里每个词打分，再挑一个作为下一个词。这本 notebook 教你在挑之前怎样调分数、怎样缩小候选范围，让输出更确定或者更多样。

## 为什么需要它

模型每走一步，会给词表里的每个词元打一个分，分越高表示越想选它。怎么从这些分数里挑出下一个词元，有两条最简单的路：

- 贪心解码：每次都选分最高的那个。结果确定，同样的输入永远得到同样的输出，但没有变化。
- 采样解码：先把分数变成加起来等于 1 的概率，再按概率随机抽一个。有变化了，但抽到哪个全凭概率。

只在这两条路里选，取舍的余地很小：要么完全确定，要么完全照着模型给的概率随机。这本 notebook 在“挑”之前加了三道处理：用温度调整分数的差距，用 Top-K 和 Top-p 缩小候选集合。它们只处理本轮的分数，不改模型权重；选出来的词元会进入下一轮的上下文，所以会影响后面的生成。词表分数本身是怎么算出来的不是本节重点，notebook 的前置阅读列了 04 注意力机制。

## 先认识几个词

| 词 | 人话解释 |
|:---|:---|
| 词表（vocabulary） | 模型能输出的全部词元。本节用一排分数表示，每个位置对应一个词元 |
| 词表分数（logits） | 模型在当前位置给每个词元打的分。它还不是概率，加起来不等于 1 |
| 贪心解码（greedy） | 每次选分数最高的词元，结果确定 |
| 采样解码（sampling） | 先把分数变成概率，再按概率随机抽一个词元 |
| 温度（temperature） | 一个正数 `T`。所有分数都除以它，排序不变，概率的集中程度改变 |
| Top-K / Top-p | 两种缩小候选集合的过滤。Top-K 按排名留前 K 个，Top-p 按累计概率留到够数为止 |
| 候选集合 | 过滤之后还有机会被选中的词元。集合外的位置被设成负无穷，Softmax 后概率是 0 |

## 核心思路

输入是一排词表分数，形状是 `[vocab]` 或 `[batch, vocab]`。骨架代码按固定顺序处理它，其中前三步是你要补的：

```text
词表分数 → ① 除以温度 T → ② Top-K：只留排名靠前的 → ③ Top-p：按累计概率截断
         → ④ Softmax 归一化 → ⑤ 选择：贪心取最大值，采样按概率抽
```

① 温度。把每个分数 `z` 换成 `z / T`。所有分数除以同一个正数，谁大谁小不变，但分数之间的差距变了，Softmax 之后的概率有的更集中、有的更平。温度很低时概率向最高分集中，但只要走采样路径，仍可能抽到别的词元，所以它不等同于贪心解码。

② Top-K。取第 K 大的分数当门槛，低于门槛的位置设成负无穷，其余原样保留。和门槛相等的词元一起留下，所以候选数可能超过 K。

③ Top-p。先把分数从高到低排序并算出概率，再从前往后累加。累计值第一次达到或超过 `p` 的那个词元是边界，它和它前面的都留下，后面的屏蔽。最后要把顺序恢复成原来的词表顺序。

下面用 4 个词元的分数看前两步，再用 notebook Step 3 的例子看 Top-p 的边界：

```python
import torch

scores = torch.tensor([2.0, 1.0, 0.5, 0.1])          # 4 个词元的分数，已按从高到低排好
for t in (1.0, 0.5, 2.0):
    print(torch.softmax(scores / t, dim=-1))         # 温度分别是 1、0.5、2

keep = scores >= torch.topk(scores, 2).values[-1]    # Top-2：不低于第 2 大分数的位置才保留
print(keep, torch.softmax(torch.where(keep, scores, float('-inf')), dim=-1))

probs = torch.tensor([0.5, 0.3, 0.1, 0.05, 0.05])    # notebook Step 3 的例子，已按概率从高到低排好
remove = torch.cumsum(probs, dim=-1) >= 0.85         # 累计概率达到阈值的位置
print(remove)
shifted = remove[:-1].clone()                        # 右移一位，把首次达到阈值的位置留下来
remove[1:] = shifted
remove[0] = False
print(remove)
```

```text
tensor([0.5745, 0.2114, 0.1282, 0.0859])
tensor([0.8282, 0.1121, 0.0412, 0.0185])
tensor([0.4056, 0.2460, 0.1916, 0.1569])
tensor([ True,  True, False, False]) tensor([0.7311, 0.2689, 0.0000, 0.0000])
tensor([False, False,  True,  True,  True])
tensor([False, False, False,  True,  True])
```

前四行是温度等于 1、0.5、2 时的概率：温度 0.5 时最高分词元的概率从 0.5745 升到 0.8282，温度 2 时降到 0.4056，但四个词元的大小顺序始终没变。第五行是 Top-2：保留前两个位置后，被屏蔽的位置概率是 0，留下的两个概率加起来仍然是 1。

最后两行是 Top-p。累计概率依次是 0.5、0.8、0.9、0.95、1.0，到第三个词元才第一次超过 0.85。`remove` 把第三个也标成了要删，所以要整体右移一位：第三个留下来，第四、第五个删掉。第一个位置强制保留。如果累计值恰好等于阈值，也在那里停下，不再多留一个。

## 容易踩的坑

- **温度当成乘法，或者放过了非法值**：是除以 `T`，而且 `T` 必须是有限正数，`0` 要报 `ValueError`。缩放后排序、形状、数据类型和设备都不能变。
- **Top-K 只保留恰好 K 个**：第 K 大的分数是门槛，所有不低于门槛的位置都保留。测试里 `[2.0, 2.0, 2.0, 1.0]` 取 K 等于 2，留下的是 3 个。
- **Top-p 删掉了边界词元**：累计概率首次达到阈值的词元必须保留，恰好等于阈值时也停在那里。既不能多删，也不能再多留一个。
- **过滤完忘了恢复词表顺序**：Top-p 是在排序后的空间里找边界，结果要用 `scatter_` 放回原来的位置。测试会核对位置 5、6、1 上的分数和原来完全一样。
- **以为温度很低就等于贪心**：采样路径仍可能选到非最高分的词元。要确定的结果，得走贪心路径。
