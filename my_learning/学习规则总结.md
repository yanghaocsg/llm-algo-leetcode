## 一、打卡机制

### 1.1 核心规则
- **务必在任务截止时间前完成打卡**，并在群里接龙且附带打卡截图。
- 打卡机制也是**筛选机制**：未在规定时间内打卡、打卡不规范的，都会被移出学习群。
- 被移出后想回来：找到运营助教提交**有效打卡截图**，即可被拉回学习群。

### 1.2 规范打卡："两步走"与"三要素"

**第一步**：在 GitHub 指定 issue 链接中上传测试通过截图，作为打卡。

**第二步**：把自己的打卡截图发到群里。微信群截图需**三要素清晰可见**：
1. **issue 标题** — 确保找对了 GitHub issue 地址
2. **GitHub ID** — 身份标识
3. **微信群昵称** — 用于匹配到人

> ⚠️ **警告**：为留在群里制作假截图，被发现后直接移出群。

### 1.3 Task 0 特别说明
- Task 0 的完成需要一定的主观能动性、学习能力和行动力。
- **Task 0 没有完成打卡是会被筛选出群的。**
- Task 0 的作用：快速熟悉打卡规则和教程使用，给你一个启动的 ddl。
- issue 打卡机制的好处：在大模型 agent 盛行的今天，去学习别人的作业。

### 1.4 筛选时间
- 请尽量按时打卡。
- 会给大家一定的**补卡时间**；筛选人不是目的，督促大家学习才是真的。
- 如果确实没有时间学习，这是一个双向选择。

## 二、打卡常见问题 Q&A

### Q: 为什么要用 GitHub issue 打卡、写微信群昵称、群内接龙并附截图？
- **截图要有 issue 标题**：因为部分人会找不对 GitHub issue 地址。
- **写微信群昵称**：为了匹配到人。
- 群里一张"issue 标题、微信群昵称、GitHub ID"截图，就能直接有效说明确实有打卡记录。
- **群内接龙**：方便助教知道有多少人打卡，对学习者能有打卡时间提醒、看到最重要的打卡链接。

### Q: 因微信群没发截图或打卡不规范被移出群怎么办？
- **只接龙不发截图不 OK**：接龙方便集中统计，顺手把截图发到群里。
- 筛选的时候，看的是群里的截图，因为工作量小。
- 需要群外追平进度后，联系运营助教返回群。

## 四、提问姿势与学习心得

### 4.1 有问题问谁：向谁求助
**优先先自我排查**：翻看教程、搜索资料、自己调试。

自己无法解决后，可以：
- 带着自己的思考向助教提问
- 在群里向大家提问
- 看他人作业学习参考

> ❌ 不要直接抄别人作业当做解决手段。
> ❌ 不要频繁私戳助教，先确认该问题是否适合在群内讨论。
> ✅ 求助优先选择公开学习群。

### 4.2 如何提问：怎样的问题是清晰、客观的？
提问前记录自己已经做过的尝试：
- 查阅了哪部分教程
- 搜过哪些关键词
- 自己做过哪些调试

写清**现象、报错**，不要只描述主观感受。
- ❌ 不要一次性抛出一大堆模糊问题
- ❌ 不要直接索要完整答案
- ✅ 尽量描述你希望得到**方向、提示**，而不是直接要最终结果

### 4.3 学习预期
- 教程面向全体学习者做通用设计，很难 100% 贴合每个人的个性化需求，属于正常情况。
- 不要期待教程直接解决你的全部个人场景，需要自己结合教程内容做**迁移思考**。

### 4.4 多次学习
- 教程每月学习计划会迭代更新，本期内容不一定完全适配你的旧基础。
- 学习不需要全部啃完，可以**分层选取**对应自己目标的内容，后续可以返场复看迭代后的新版本。

### 4.5 提问心态
- 别人的回复是无偿的经验分享，没有义务给出你心中预想的答案。
- 回复和预期不一致时：
  1. 先思考对方回答背后的思路
  2. 反思是否自己问题描述存在偏差、自身问题存在错误前提
  3. 如果仍然无法解决，可以补充自己新的思考再重新提问
  4. ❌ 而不是否定他人回复
